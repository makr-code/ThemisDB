# Utils Module Tests

This directory contains focused tests for the public and internal utility
contracts, including privacy detection, audit logging, codecs, cryptographic
helpers, rate limiting, serialization, resource management, and concurrency.
The inventory changes with the implementation; use CMake registration as the
source of truth rather than a fixed file or test count.

## Registration

The root `tests/CMakeLists.txt` adds module directories that contain a
`CMakeLists.txt`. `tests/utils/CMakeLists.txt` registers selected test targets
explicitly and discovers `test_utils_*.cpp` files as focused tests. Optional
codec tests are compiled with feature definitions only when the corresponding
dependencies are available. The module registration helper labels tests with
`module:utils`.

## Build and run

From the repository root, configure the existing community debug preset and
build a focused target:

```bash
cmake --preset community-debug
cmake --build build-community-debug --target module_utils_test_utils_pii_unicode_edge_cases_autofocused -j4
ctest --test-dir build-community-debug -L module:utils --output-on-failure
```

The target example is generated by the `test_utils_*.cpp` CMake rule. To
inspect available targets or registered tests in a configured build, use:

```bash
cmake --build build-community-debug --target help
ctest --test-dir build-community-debug -N -L module:utils
```

The module has no single aggregate `module_utils_test` target. See
[`PHASE_4_TEST_EXECUTION_GUIDE.md`](PHASE_4_TEST_EXECUTION_GUIDE.md) for the
focused execution workflow and the module
[`ROADMAP.md`](../../src/utils/ROADMAP.md) for historical test-phase records.
