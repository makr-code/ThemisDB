# ONNX CLIP focused tests

## What is registered

When `THEMIS_PLUGIN_IMAGE_ANALYSIS_ONNX` is enabled, this directory's
`CMakeLists.txt` globs `test_*_focused.cpp` and registers one executable/CTest
entry for each matching file. The three matching files in this checkout are:

| Source | Named cases | What they check |
|---|---:|---|
| `test_onnx_clip_golden_embeddings_focused.cpp` | 12 (`OCP_IT_01..12`) | Initialization/readiness; generated-byte reference vectors; configured dimensions and normalization; repeatability, batch equivalence, statistics, and concurrent calls. |
| `test_onnx_clip_hot_swap_focused.cpp` | 12 (`OCP_HS_01..12`) | Reload/readiness and generated-input request checks; not ONNX model replacement. |
| `test_onnx_clip_mmap_focused.cpp` | 12 (`OCP_MM_01..12`) | Best-effort mapping of generated mock files and reference-vector behavior; the memory-labelled cases do not establish memory savings. |

These are source-defined test cases, not a record that they have been built or
passed. The golden test's `ViT-B/32` and `ViT-L/14` names are configuration
labels; the plugin uses the configured dimension and does not load either model.
Its `kClipGoldenSeed` is 42 and its image bytes are generated by an LCG; despite
the test filename, there is no stored reference-vector golden file or comparison
to model output. The tests check properties such as reproducibility,
normalization, and dimensions. Inputs and mock files do not validate inference
or semantic quality.

## What the assertions establish

### Golden embeddings (`OCP_IT_01..12`)

- `OCP_IT_01` and `OCP_IT_02` check successful initialization, readiness, CPU
  backend, and health. They do not assert that a model variant was loaded.
- `OCP_IT_03` checks one generated-byte result is successful, nonzero,
  512-dimensional, and normalized. `OCP_IT_04` checks four batch results for
  success, dimensions, and normalization. `OCP_IT_05` checks normalized outputs
  at 512 and 768 dimensions; `OCP_IT_06` checks dimensions, including the batch
  result dimension field. The model-name/variant labels do not select weights.
- `OCP_IT_07`, `OCP_IT_09`, and `OCP_IT_10` check repeatability or equivalence
  between repeated, single, and batch calls; the latter two also check success,
  dimensions, and normalization. `OCP_IT_11` compares outputs across three
  plugin instances.
- `OCP_IT_08` checks health before/after initialization and shutdown, and checks
  statistics are an object containing at least one of `backend`, `calls`, or
  `model_variant`; it does not assert particular counter values.
- `OCP_IT_12` runs four threads with two generated inputs each and checks their
  results through the helper, then checks health. It is not a sanitizer or
  general race-freedom proof.

### Hot swap (`OCP_HS_01..12`)

- Every case has a conditional `GTEST_SKIP()` if the fixture's plugin is not
  ready; the checks are therefore conditional on successful initialization.
- `OCP_HS_03` checks readiness before/after reload; it does not observe the
  intermediate state sequence mentioned in its comment.
- `OCP_HS_05` accepts either a successful result of the configured size or a
  failure with a non-empty error message.
- `OCP_HS_06` starts two workers and asserts reload succeeds and that at least
  one request completed; it does not assert that all ten worker iterations ran.
- `OCP_HS_07` tests an idle reload with a five-second upper bound. It does not
  trigger the implementation's 30-second drain timeout.
- `OCP_HS_08` starts three workers with three calls each and checks nine result
  objects were collected, but does not check each result's success.
- `OCP_HS_09` starts two inference workers and asserts reload succeeds; it does
  not assert a minimum inference count. `OCP_HS_12` performs calls before and
  after reload sequentially and checks readiness and vector counts, not result
  validity. `OCP_HS_10` and `OCP_HS_11` do check successful, 512-element outputs
  before/after reload.

### Mmap (`OCP_MM_01..12`)

- `OCP_MM_01..04` check initialization/readiness with a mock file, nonexistent
  path, empty path, or two-byte file. `OCP_MM_02` does not test traditional model
  loading; `OCP_MM_03` does not test an invalid non-empty path or diagnostic.
- `OCP_MM_05` compares generated vectors from mmap-enabled and disabled plugin
  instances; it does not compare model inference.
- `OCP_MM_06..08` check batch, text, and four-thread output properties using
  generated inputs; they do not establish model behavior.
- `OCP_MM_09` reads RSS values but discards them without comparing. `OCP_MM_10`
  checks success and equal vector sizes; `OCP_MM_11` checks success and expected
  vector sizes. Neither reads RSS or compares the percentage thresholds named
  in its comments. `OCP_MM_12` checks ten batches of eight successful results
  and non-null statistics, not memory bounds or leaks. `OCP_MM_09` is
  conditionally skipped on Windows.

`test_onnx_clip_highcardinality_stress.cpp` is present but is **not** selected by
the local glob because its name does not end in `_focused.cpp`. It contains
simulation-only `Stub*` counters/reloader, not calls to `ONNXClipPlugin`; it is
not registered by the local focused-test target.

## Build boundary

The local test targets are conditional on
`THEMIS_PLUGIN_IMAGE_ANALYSIS_ONNX`. CMake names each target
`module_onnx_clip_${_stem}_focused`, where `_stem` already ends in
`_focused`; use the resulting exact target names below rather than a shell
wildcard:

| Source stem | CMake target | CTest name |
|---|---|---|
| `test_onnx_clip_golden_embeddings_focused` | `module_onnx_clip_test_onnx_clip_golden_embeddings_focused_focused` | `test_onnx_clip_golden_embeddings_focused_OnnxClipFocused` |
| `test_onnx_clip_hot_swap_focused` | `module_onnx_clip_test_onnx_clip_hot_swap_focused_focused` | `test_onnx_clip_hot_swap_focused_OnnxClipFocused` |
| `test_onnx_clip_mmap_focused` | `module_onnx_clip_test_onnx_clip_mmap_focused_focused` | `test_onnx_clip_mmap_focused_OnnxClipFocused` |

In modular builds, or when the shared plugin target is absent, CMake compiles
`src/onnx_clip/onnx_clip_plugin.cpp` directly into each test executable.
Otherwise the tests link the plugin target.
Each registered CTest entry has a 120-second timeout.

CTest registers one entry per focused executable, not one entry per internal
GoogleTest case. Therefore `ctest -R OCP_IT`, `ctest -R OCP_HS`, and
`ctest -R OCP_MM` do not select these entries by their GoogleTest case names.
Select an executable-level CTest entry, for example:

```bash
ctest -R '^test_onnx_clip_golden_embeddings_focused_OnnxClipFocused$'
```

For an individual GoogleTest case, invoke the built focused executable with
`--gtest_filter`, for example:

```bash
<path-to-focused-executable> \
    --gtest_filter='OnnxClipGoldenEmbeddingsTest.OCP_IT_01_InitializeViTB32Config'
```

The current CTest wrapper does not forward an ad hoc GoogleTest filter from the
`ctest` command line; use the executable directly for case-level selection.

The CMake file optionally links ONNX Runtime and OpenCV when found. The
implementation currently calls neither API; those links do not make these
model-backed tests. This review did not configure or build the targets and did
not run tests.
