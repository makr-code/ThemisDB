# Security — Process Modeling Module

## Threat Model

### 1. Malicious BPMN / EPK / VCC-VPB Input
- **Risk:** An attacker supplies a crafted BPMN XML, EPK text, or VCC-VPB YAML file
  designed to exploit the parser (billion-laughs XML expansion, stack overflow via
  deeply nested structures, oversized payloads).
- **Mitigation:** `BpmnSerializer` uses a hand-written state-machine XML tokenizer (`tokenizeXml`) — no DOM/SAX
  library is used, eliminating entity-expansion attacks. The 10 MiB document guard rejects oversized inputs.
- **Status:** ✅ Entity-expansion not possible (no XML entity resolver); field validation present

### 2. Unauthorised Process Model Access
- **Risk:** A caller reads or overwrites process models belonging to another tenant.
- **Mitigation:** Process model records are stored under the `proc:def:{id}` key prefix
  in RocksDB. Access control is enforced at the ThemisDB authentication and authorisation
  layer (`src/auth/`). The Process module does not bypass auth checks.
- **Status:** ✅ Delegated to ThemisDB core auth

### 3. Path Traversal in VCC-VPB Directory Import
- **Risk:** `VccVpbImporter::importDirectory()` scans a caller-supplied directory path.
  A crafted path with `../` components could cause the importer to read files outside
  the intended directory.
- **Mitigation:** The directory path is passed to the OS filesystem scan; no explicit
  path normalisation is performed. Callers must validate the path before passing it
  to `importDirectory()`. The ThemisDB server API layer must restrict allowed import
  paths to a configured whitelist.
- **Status:** ⚠️ No explicit path normalisation in the module; API layer responsibility

### 4. LLM Prompt Injection via Process Model Content
- **Risk:** A process model with crafted node names or descriptions containing LLM
  instruction-injection strings is ingested, and those strings are later embedded
  in an LLM system prompt generated by `LlmProcessDescriptor` or `ProcessGraphRag`.
- **Mitigation:** `LlmProcessDescriptor::generate()` and `ProcessGraphRag` produce
  the LLM context in the `llm_context` field as a structured, delimited block.
  Callers injecting this into an LLM system prompt must treat it as untrusted user
  content (inject in the `user` role, not `system`) and apply their LLM provider's
  prompt-injection guardrails.
- **Status:** ⚠️ Structural mitigation only; caller LLM injection policy required

### 5. Denial of Service via Large Process Models
- **Risk:** A caller imports a BPMN model with 10,000+ nodes, causing
  `ProcessGraphRag::buildKnowledgeGraph()` to allocate gigabytes of memory.
- **Mitigation:** `ProcessRagConfig` includes `max_nodes` and `max_depth` fields
  that bound subgraph extraction. `extractSubgraph()` respects the `max_depth`
  parameter for BFS traversal. An explicit per-import node count limit is planned
  for v1.1.0.
- **Status:** ⚠️ Subgraph bounded; full model size not yet capped at import time

### 6. AQL Injection via Query Parameters
- **Risk:** Caller-supplied strings (model IDs, category filters) passed to AQL
  queries are interpolated directly, enabling AQL injection.
- **Mitigation:** Model IDs and key values follow the ThemisDB key naming convention
  (`proc:def:{id}`) and are used as RocksDB key prefixes, not in AQL string
  interpolation. AQL queries in `ProcessModelManager` use parameterised bind variables
  where applicable.
- **Status:** ✅ Key-based access; parameterised AQL for collection queries

## Security Controls Summary

| Control | Implementation | Status |
|---------|---------------|--------|
| XML entity-expansion prevention | State-machine tokenizer (`tokenizeXml`); no DOM/SAX entity resolver; 10 MiB size guard | ✅ |
| Input field validation | Required-field checks in all serialisers | ✅ |
| Access control | Delegated to ThemisDB auth layer | ✅ |
| Subgraph size bound | `ProcessRagConfig::max_depth` in `extractSubgraph()` | ✅ |
| Parameterised AQL | Bind variables for collection queries | ✅ |
| Path traversal prevention | API layer responsibility; no module-level normalisation | ⚠️ |
| LLM prompt injection | Structural delimiters; caller injection policy required | ⚠️ |

## Known Limitations

| ID | Description | Severity | Status |
|----|-------------|----------|--------|
| PROC-SEC-01 | No per-import node count limit; very large models not rejected at ingest | High | Open (planned v1.1.0) |
| PROC-SEC-02 | No path normalisation in `VccVpbImporter::importDirectory()` | Medium | Open |
| PROC-SEC-03 | LLM prompt injection risk from crafted process model node names | Medium | Open (caller policy required) |
| PROC-SEC-04 | Compliance tags not verified against a trusted allowlist; arbitrary tags accepted | Low | Open |
