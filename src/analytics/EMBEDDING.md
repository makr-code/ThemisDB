# Analytics Embedding and Vector Features

## Scope and trust boundary

Analytics does not define a general pretrained text-embedding service. Its
embedding-related code consists of deterministic feature projections for
process activity names and optional vectors supplied by callers. Embedding
model selection, training, versioning, and semantic quality therefore remain
outside these interfaces unless an application injects and governs them.

## Built-in process-pattern vectorization

[`ProcessPatternMatcher`](../../include/analytics/process_pattern_matcher.h)
creates a fixed 2,048-element vector from activity names. The implementation
pads each activity with a space, counts character trigrams into hash buckets,
then L2-normalizes the combined vector. It compares pattern and trace vectors
using cosine similarity. This is a lightweight lexical feature map: collisions
are possible, and semantic equivalence is not inferred when activity labels use
unrelated wording.

An optional `ProcessPattern::pattern_embedding` lets a caller supply a
precomputed pattern vector. The trace-side vector is still generated by the
built-in projection. Keep the supplied vector dimension and representation
compatible with the trace side; vectors from an unrelated model are not
meaningful drop-in replacements. Empty patterns/traces do not provide useful
vector-similarity evidence; use graph or behavioral signals where appropriate.

`ProcessMining` also contains a separate fixed-length hash-based projection for
variant clustering. Do not treat those vectors as interchangeable with the
pattern matcher's 2,048-element trigram vectors.

## Injected adapter-selection vectors

[`LoRAPatternClassifier`](../../include/analytics/lora_pattern_classifier.h)
accepts an `EmbeddingFn` callback and registered `AdapterDomain` vectors.
`selectAdapter(context)` embeds the context with that callback and selects by
cosine similarity. If no callback is set, or callback evaluation throws, it
chooses the first registered adapter. Empty or dimension-mismatched vectors
produce no useful similarity distinction. The caller must ensure that context
and registered vectors come from the same model/version and feature space.

The callback runs as part of adapter selection; configure it before concurrent
classification. The header explicitly disallows concurrent callback/domain
updates with classification.

## Related but distinct text features

[`NlpTextAnalyzer`](../../include/analytics/nlp_text_analyzer.h) extracts
keywords with TF-IDF and supplies heuristic tokenization, stop-word,
stemming/lemmatization, sentiment, and entity-pattern operations. It does not
return dense neural embeddings. Its built-in sentiment lexicon and regular
expression entity rules have dictionary/pattern coverage limits; evaluate them
against the application's language and text distribution.

## Evaluation and operational guidance

- Compare pattern matches against labeled trace pairs and retain each score
  component, not only the hybrid total.
- Measure false positives caused by shared character trigrams and false
  negatives caused by different labels for the same activity.
- For injected vectors, persist provider/model/version and dimensionality with
  the caller's configuration; reject incompatible vectors before serving.
- Do not use a similarity score as authorization, identity, or a security
  decision.
- Review [`test_process_pattern_matcher.cpp`](../../tests/analytics/test_process_pattern_matcher.cpp)
  and [`test_process_mining_llm.cpp`](../../tests/analytics/test_process_mining_llm.cpp)
  when changing matching or process-vector behavior.
