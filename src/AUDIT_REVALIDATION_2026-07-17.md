# ThemisDB S0 Findings Re-Audit — 2026-07-17

## Executive Summary

Re-read `src/AUDIT.md` and revalidated all 23 historical S0 claims against the current source tree.
Current status: **17 findings are fixed**, **4 are partially fixed**, **2 are not directly re-auditable at the original path because the file moved/was replaced**, and **0 were confirmed as still vulnerable** in the current tree.

The main residual risk areas are:
- **query ACL coverage** in `src/query/query_engine.cpp` (`QE-2`)
- **conditional privilege enforcement** in `src/aql/llm_aql_handler.cpp` (`LLM-2`)
- **optional trusted-base enforcement** in `src/llm/multi_lora_manager.cpp` (`F1-1`, `F1-2`)

## Residual Risks / Follow-ups

1. **`QE-2`**: add explicit collection ACL enforcement to `executeJoin()` and `executeGroupBy()` before `db_->scanPrefix(...)` on every collection-derived path.
2. **`LLM-2`**: make privilege enforcement fail closed when `schema_context` is absent or no `collection_access_checker_` is configured.
3. **`F1-1` / `F1-2`**: remove or tightly gate the current “legacy mode” that disables trusted-base validation when `lora_base_dir` is empty.
4. **`SH-1` / `SH-7`**: if historical traceability matters, link the retired `paxos_coordinator.cpp` findings to the replacement Paxos implementation in a sharding-specific audit note.

## Methodology & Limitations

- Primary source reviewed in full: `src/AUDIT.md`.
- Revalidation used **current repository source code only**, with line-by-line inspection of the cited implementation files and replacement paths where the original file no longer exists.
- This was a **static code re-audit**, not a runtime exploit exercise; no proof-of-concept execution, fuzzing, or dynamic concurrency testing was performed.
- Line numbers reflect the repository state at audit time (`2026-07-17`) and may shift with later edits.
