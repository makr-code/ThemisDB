# COPILOT INSTRUCTIONS: ThemisDB CMake Build System

**Directory:** `cmake/`  
**Purpose:** Modular CMake build system with platform detection, edition orchestration, and cross-compile support  
**Target Users:** Developers, CI/CD systems, cross-platform builders

---

## 📋 OVERVIEW

The ThemisDB CMake build system is organized into 4 main categories:
1. **platforms/** - Platform detection, architecture optimization, cross-compile toolchains
2. **editions/** - Edition-based feature restrictions (MINIMAL, COMMUNITY, ENTERPRISE, HYPERSCALER)
3. **features/** - Feature organization by domain (LLM, Network, GPU, Security, Tools, Optimizations)
4. **validation/** - Configuration validation (platform, edition, feature constraints)

---

## 🏗️ BUILD ORDER (CRITICAL)

**The include order in root `CMakeLists.txt` MUST be respected:**

```cmake
1. cmake/Versions.cmake                           # Version info ONLY
2. cmake/CompilerOptions.cmake                    # Compiler settings
3. cmake/platforms/PlatformDetection.cmake        # OS, CPU, triplet detection
4. cmake/platforms/ArchitectureOptimizations.cmake # AVX2, NEON, QNAP optimizations
5. cmake/PreloadTargets.cmake                     # Preload system packages
6. cmake/Dependencies.cmake                       # Find external packages
7. cmake/editions/EditionDefaults.cmake           # Edition selection (AFTER platform!)
8. cmake/features/FeatureDefaults.cmake           # Feature configuration (AFTER edition!)
9. cmake/validation/PlatformValidation.cmake      # Platform requirements
10. cmake/validation/EditionValidation.cmake      # Edition constraints
11. cmake/validation/FeatureValidation.cmake      # Feature dependencies
12. add_subdirectory(cmake)                       # Main build logic
```

**❌ DO NOT change this order without careful consideration!**

## 🚀 USING CMAKE PRESETS (RECOMMENDED)

CMake Presets provide pre-configured build settings for common scenarios. This is the **recommended** way to build ThemisDB.

### Quick Start with Presets

```bash
# List available presets
cmake --list-presets

# Configure using a preset
cmake --preset community-release

# Build
cmake --build --preset community-release

# Test
ctest --preset test-fast
```

## 🎯 STANDARD BUILD COMMANDS

### Default Build (COMMUNITY edition, x86_64 Linux)
```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j$(nproc)
```

### Select Edition
```bash
# MINIMAL: Core only, no LLM/gRPC/GPU (embedded systems)
cmake -S . -B build -DTHEMIS_EDITION=MINIMAL -DCMAKE_BUILD_TYPE=Release

# COMMUNITY: Standard features, optional LLM/gRPC/GPU (default)
cmake -S . -B build -DTHEMIS_EDITION=COMMUNITY -DCMAKE_BUILD_TYPE=Release

# ENTERPRISE: Advanced features, HSM, multi-shard
cmake -S . -B build -DTHEMIS_EDITION=ENTERPRISE -DCMAKE_BUILD_TYPE=Release

# HYPERSCALER: All features, unlimited resources
cmake -S . -B build -DTHEMIS_EDITION=HYPERSCALER -DCMAKE_BUILD_TYPE=Release
```

### Enable/Disable Features
```bash
# Disable LLM support
cmake -S . -B build -DTHEMIS_ENABLE_LLM=OFF

# Enable GPU with CUDA backend
cmake -S . -B build -DTHEMIS_ENABLE_GPU=ON -DTHEMIS_ENABLE_CUDA=ON

# Enable gRPC networking
cmake -S . -B build -DTHEMIS_ENABLE_GRPC=ON

# Enable all Phase 1 optimizations
cmake -S . -B build -DTHEMIS_ENABLE_RCU_INDEX=ON -DTHEMIS_ENABLE_LIRS_CACHE=ON
```

### Architecture-Specific Builds
```bash
# x86_64 with AVX2 (default on non-QNAP)
cmake -S . -B build -DTHEMIS_ENABLE_AVX2=ON

# QNAP NAS build (SSE4.2 only, no AVX)
cmake -S . -B build -DTHEMIS_QNAP_BUILD=ON

# Disable ARM NEON on ARMv7
cmake -S . -B build -DTHEMIS_ENABLE_ARM_NEON=OFF
```

## 🔀 CROSS-COMPILATION

### Using CMake Presets (Recommended)

**ARM64 Linux:**
```bash
cmake --preset cross-arm64
cmake --build --preset cross-arm64
```

**ARMv7 Linux (Raspberry Pi):**
```bash
cmake --preset cross-armv7
cmake --build --preset cross-armv7
```

### Manual Cross-Compilation with Toolchain Files

### ARM64 Cross-Compile (from x86_64 Linux)
```bash
# Install cross-compiler
sudo apt-get install gcc-aarch64-linux-gnu g++-aarch64-linux-gnu

# Configure
cmake -S . -B build-arm64 \
  -DCMAKE_TOOLCHAIN_FILE=cmake/platforms/Toolchains/arm64-linux-gnu.cmake \
  -DTHEMIS_EDITION=COMMUNITY \
  -DVCPKG_TARGET_TRIPLET=arm64-linux \
  -DCMAKE_BUILD_TYPE=Release

# Build
cmake --build build-arm64 -j$(nproc)
```

### ARMv7 Cross-Compile (Raspberry Pi 2/3)
```bash
# Install cross-compiler
sudo apt-get install gcc-arm-linux-gnueabihf g++-arm-linux-gnueabihf

# Configure
cmake -S . -B build-armv7 \
  -DCMAKE_TOOLCHAIN_FILE=cmake/platforms/Toolchains/armv7-linux-gnueabihf.cmake \
  -DTHEMIS_EDITION=MINIMAL \
  -DVCPKG_TARGET_TRIPLET=arm-linux \
  -DCMAKE_BUILD_TYPE=Release

# Build
cmake --build build-armv7 -j$(nproc)
```

### Windows MinGW Cross-Compile (from Linux)
```bash
# Install MinGW-w64 cross-compiler
sudo apt-get install mingw-w64

# Configure
cmake -S . -B build-mingw \
  -DCMAKE_TOOLCHAIN_FILE=cmake/platforms/Toolchains/x86_64-w64-mingw32.cmake \
  -DTHEMIS_EDITION=COMMUNITY \
  -DVCPKG_TARGET_TRIPLET=x64-mingw-static \
  -DCMAKE_BUILD_TYPE=Release

# Build
cmake --build build-mingw -j$(nproc)
```

### Docker Multi-Architecture Build
```bash
# Build for amd64, arm64, and armv7
docker buildx build \
  --platform linux/amd64,linux/arm64,linux/arm/v7 \
  --build-arg THEMIS_EDITION=COMMUNITY \
  -t themisdb/themisdb:latest \
  .
```

### Available Toolchain Files

| File | Target Platform | Compiler | vcpkg Triplet |
|------|----------------|----------|---------------|
| `arm64-linux-gnu.cmake` | ARM64 Linux | aarch64-linux-gnu-gcc | arm64-linux |
| `armv7-linux-gnueabihf.cmake` | ARMv7 Linux | arm-linux-gnueabihf-gcc | arm-linux |
| `x86_64-w64-mingw32.cmake` | Windows x64 | x86_64-w64-mingw32-gcc | x64-mingw-static |
| `windows-msvc.cmake` | Windows x64 | cl (MSVC) | x64-windows |

## 📂 DIRECTORY STRUCTURE DETAILS

### `platforms/` - Platform Detection & Optimization

**PlatformDetection.cmake**
- Detects: Linux, Windows, macOS, Docker environments
- Detects: x86_64, ARM64 (aarch64), ARMv7 architectures
- Special platforms: QNAP NAS, Raspberry Pi
- Maps to vcpkg triplets: `x64-linux`, `arm64-linux`, `arm-linux`
- Cross-compile detection with warnings

**Variables set:**
- `THEMIS_TARGET_ARCH`: x86_64, aarch64, armv7, unknown
- `THEMIS_TARGET_PLATFORM`: linux, windows, macos, docker, raspberry-pi, qnap
- `THEMIS_TARGET_ARCH_TRIPLET`: vcpkg triplet for dependencies
- `THEMIS_PLATFORM_DETECTED`: TRUE (flag for validation)

**ArchitectureOptimizations.cmake**
- Applies optimizations only in Release mode
- Skipped during cross-compilation (handled by toolchain)

**Optimizations:**
- x86_64: `-march=native` (AVX2+FMA) OR `-march=x86-64 -msse4.2` (QNAP)
- ARM64: `-march=armv8-a` (NEON standard)
- ARMv7: `-march=armv7-a -mfpu=neon` (optional)

**Toolchains/**
- `arm64-linux-gnu.cmake`: ARM64 cross-compile
- `armv7-linux-gnueabihf.cmake`: ARMv7 cross-compile (with NEON)
- `amd64-linux-gnu.cmake`: x86_64 cross-compile
- `windows-msvc.cmake`: Windows MSVC build

### `editions/` - Edition System

**EditionDefaults.cmake**
- Validates `THEMIS_PLATFORM_DETECTED` is set (must come after PlatformDetection)
- Selects edition: MINIMAL, COMMUNITY (default), ENTERPRISE, HYPERSCALER
- Loads edition-specific file
- Sets compile definition: `THEMIS_EDITION_<NAME>`

**MINIMAL.cmake**
- **Purpose:** Embedded systems, IoT, edge devices
- **Hardware limits:** 1 node, 128 MB cache, no GPU
- **Features:** Core database only
- **Disabled:** LLM, gRPC, GPU, all protocols, cloud storage, HSM
- **Compile defs:** `THEMIS_MINIMAL_EDITION`, `THEMIS_GPU_MAX_VRAM_GB=0`, `THEMIS_SHARDING_MAX_NODES=1`

**COMMUNITY.cmake**
- **Purpose:** Standard deployments, small teams
- **Hardware limits:** 5 nodes, 1 GB cache, 16 GB GPU VRAM (1× Tesla T4)
- **Features:** Core + optional LLM/gRPC/GPU
- **User-configurable:** All features can be enabled/disabled
- **Compile defs:** `THEMIS_COMMUNITY_EDITION`, `THEMIS_GPU_MAX_VRAM_GB=16`, `THEMIS_SHARDING_MAX_NODES=5`

**ENTERPRISE.cmake**
- **Purpose:** Enterprise deployments, production systems
- **Hardware limits:** 100 nodes, 4 GB cache, 320 GB GPU VRAM (4× A100 80 GB)
- **Features:** Advanced features, HSM support, multi-shard
- **Required:** gRPC must be enabled
- **Available:** Real HSM provider
- **Compile defs:** `THEMIS_ENTERPRISE_EDITION`, `THEMIS_GPU_MAX_VRAM_GB=320`, `THEMIS_SHARDING_MAX_NODES=100`

**HYPERSCALER.cmake**
- **Purpose:** Cloud hyperscalers, maximum performance
- **Hardware limits:** No limits (0 = unlimited)
- **Features:** All features enabled by default
- **Enabled:** LLM, gRPC, GPU, OpenTelemetry tracing, distributed training
- **Compile defs:** `THEMIS_HYPERSCALER_EDITION`, `THEMIS_GPU_MAX_VRAM_GB=0`, `THEMIS_SHARDING_MAX_NODES=0`

### `features/` - Feature Organization

**FeatureDefaults.cmake**
- Validates `THEMIS_EDITION_SELECTED` is set
- Includes all feature modules
- Sets global flag: `THEMIS_FEATURES_CONFIGURED`

**LLMFeatures.cmake**
- `THEMIS_ENABLE_LLM`: LLM plugin (ON for COMMUNITY/ENTERPRISE/HYPERSCALER)
- `THEMIS_ENABLE_VISION`: CLIP-based vision (requires LLM)
- `THEMIS_ENABLE_CONTENT_PROCESSORS`: Content processors
- `THEMIS_ENABLE_CONTENT`: Content ingestion module

**NetworkFeatures.cmake**
- `THEMIS_ENABLE_GRPC`: gRPC (required for ENTERPRISE/HYPERSCALER)
- `THEMIS_ENABLE_HTTP_SERVER`: Built-in HTTP server (httplib)
- `THEMIS_ENABLE_HTTP2`: HTTP/2 support
- `THEMIS_ENABLE_HTTP3`: HTTP/3 support
- `THEMIS_ENABLE_WEBSOCKET`: WebSocket support
- `THEMIS_ENABLE_MQTT`: MQTT protocol
- `THEMIS_ENABLE_POSTGRES_WIRE`: PostgreSQL Wire protocol
- `THEMIS_ENABLE_MCP`: Model Context Protocol
- `THEMIS_ENABLE_SSE`: Server-Sent Events
- `THEMIS_ENABLE_GRAPHQL`: GraphQL support

**GPUFeatures.cmake**
- `THEMIS_ENABLE_GPU`: GPU acceleration (Vulkan default)
- `THEMIS_ENABLE_CUDA`: NVIDIA CUDA backend
- `THEMIS_ENABLE_HIP`: AMD HIP backend
- `THEMIS_ENABLE_ONEAPI`: Intel OneAPI backend
- `THEMIS_ENABLE_OPENCL`: OpenCL backend
- `THEMIS_ENABLE_DISTRIBUTED_TRAINING`: Multi-GPU distributed training

**SecurityFeatures.cmake**
- `THEMIS_ENABLE_TRACING`: OpenTelemetry tracing
- `THEMIS_ENABLE_HSM_REAL`: Real HSM provider
- `THEMIS_ENABLE_S3`: Amazon S3 storage backend
- `THEMIS_ENABLE_AZURE`: Azure Blob Storage backend
- `THEMIS_ENABLE_WEBDAV`: WebDAV storage backend

**ToolsFeatures.cmake**
- `THEMIS_BUILD_TESTS`: Unit tests (ON by default)
- `THEMIS_BUILD_BENCHMARKS`: Benchmarks (ON by default)
- `THEMIS_BUILD_DOCKER_RAID_BENCHMARK`: Docker RAID benchmark
- `THEMIS_STRICT_BUILD`: Warnings as errors
- `THEMIS_ENABLE_ASAN`: AddressSanitizer
- `THEMIS_CORE_SHARED`: Build core as shared library
- `THEMIS_STATIC_BUILD`: Fully static binary
- `THEMIS_ENABLE_MIMALLOC`: mimalloc allocator
- `THEMIS_ENABLE_JEMALLOC`: jemalloc allocator (alternative to mimalloc, Linux/Mac only)

**OptimizationFeatures.cmake**
- `THEMIS_ENABLE_AVX2`: AVX2 SIMD (ON by default)
- `THEMIS_QNAP_BUILD`: QNAP NAS build (SSE4.2 only)
- **Phase 1:** `THEMIS_ENABLE_RCU_INDEX`, `THEMIS_ENABLE_LIRS_CACHE`, `THEMIS_ENABLE_HUGE_PAGES`
- **Phase 2:** `THEMIS_ENABLE_WISCKEY`, `THEMIS_ENABLE_DOSTOEVSKY`, `THEMIS_ENABLE_CICADA`, etc.
- **Phase 3:** `THEMIS_ENABLE_DISKANN`, `THEMIS_ENABLE_BWTREE`, `THEMIS_ENABLE_SPLINTERDB`, etc.
- **Auto-enable:** Phase 1 features auto-enabled when building tests/benchmarks

### `validation/` - Configuration Validation

**EditionValidation.cmake**
- Validates `THEMIS_EDITION_SELECTED` and `THEMIS_FEATURES_CONFIGURED` are set
- **MINIMAL constraints:**
  - LLM, gRPC, GPU, tracing, distributed training → FATAL_ERROR
- **COMMUNITY warnings:**
  - Tracing, real HSM, distributed training → WARNING (not officially supported)
- **ENTERPRISE requirements:**
  - gRPC must be enabled → FATAL_ERROR if disabled
- **HYPERSCALER recommendations:**
  - LLM, GPU recommended → WARNING if disabled

**PlatformValidation.cmake**
- Validates `THEMIS_PLATFORM_DETECTED` is set
- **ARMv7 warnings:**
  - Raspberry Pi: "Compilation may take several hours, consider cross-compile"
  - GPU on ARMv7: Limited support warning
  - Distributed training: Not recommended
- **QNAP platform:**
  - AVX2 disabled warning (Celeron N5095 limitation)
  - GPU: Verify support on your model
- **Docker:**
  - Huge pages require privileged mode or `--cap-add=IPC_LOCK`
- **Cross-compilation:**
  - Tests/benchmarks cannot run on host system
- **Windows:**
  - Huge pages not supported (Linux-only)
- **macOS:**
  - CUDA not supported

**FeatureValidation.cmake**
- Validates `THEMIS_FEATURES_CONFIGURED` is set
- **Dependencies:**
  - Vision requires LLM → FATAL_ERROR
  - Distributed training requires GPU → FATAL_ERROR
  - GPU backends require main GPU feature → FATAL_ERROR
- **Warnings:**
  - Multiple GPU backends → binary size/build time warning
  - CUDA requires CUDA toolkit
  - Static build may cause dependency issues
  - ASAN with static build may not work
  - ASAN typically used with Debug builds
- **Conflicts:**
  - QNAP + AVX2 → auto-disable AVX2
  - Huge pages on non-Linux → auto-disable

## ⚠️ COMMON PITFALLS

### 1. Edition Not Detected
```
ERROR: EditionDefaults.cmake requires PlatformDetection.cmake to be included first
```
**Fix:** Ensure PlatformDetection.cmake is included before EditionDefaults.cmake in root CMakeLists.txt

### 2. Invalid Edition + Feature Combination
```
FATAL_ERROR: MINIMAL edition does not support gRPC. Use COMMUNITY or higher edition.
```
**Fix:** Either switch to COMMUNITY edition or disable gRPC:
```bash
cmake -S . -B build -DTHEMIS_EDITION=COMMUNITY -DTHEMIS_ENABLE_GRPC=ON
```

### 3. Cross-Compile Without Toolchain File
```
WARNING: Cross-compiling without CMAKE_TOOLCHAIN_FILE
```
**Fix:** Use the appropriate toolchain file:
```bash
cmake -S . -B build -DCMAKE_TOOLCHAIN_FILE=cmake/platforms/Toolchains/arm64-linux-gnu.cmake
```

### 4. Architecture Optimization Not Applied
```
-- Applying architecture optimizations for x86_64...
--   x86_64 optimization: Skipped (only applied in Release mode)
```
**Fix:** Configure with Release build type:
```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
```

### 5. Vision Without LLM
```
FATAL_ERROR: Vision support (THEMIS_ENABLE_VISION) requires LLM to be enabled (THEMIS_ENABLE_LLM=ON)
```
**Fix:** Enable LLM when using vision:
```bash
cmake -S . -B build -DTHEMIS_ENABLE_LLM=ON -DTHEMIS_ENABLE_VISION=ON
```

## 🔧 DEVELOPMENT GUIDELINES

### Adding a New Edition
1. Create `cmake/editions/NEWEDITION.cmake`
2. Define hardware limits: `THEMIS_GPU_MAX_VRAM_GB`, `THEMIS_SHARDING_MAX_NODES`, `THEMIS_MAX_CACHE_SIZE_MB`
3. Set feature defaults with `set(THEMIS_ENABLE_XXX ... CACHE BOOL "..." FORCE/)`
4. Add compile definitions: `add_compile_definitions(THEMIS_NEWEDITION_EDITION)`
5. Update `EditionDefaults.cmake` to recognize new edition
6. Add validation rules in `validation/EditionValidation.cmake`

### Adding a New Feature
1. Choose appropriate category: LLM, Network, GPU, Security, Tools, Optimization
2. Add to corresponding `cmake/features/XXXFeatures.cmake`
3. Define as `option(THEMIS_ENABLE_NEWFEATURE "Description" DEFAULT_VALUE)`
4. Add status message: `message(STATUS "  NewFeature: Enabled/Disabled")`
5. Add validation rules in `validation/FeatureValidation.cmake` if dependencies exist
6. Update edition files if feature should be forced ON/OFF for specific editions

### Adding a New Platform
1. Update `PlatformDetection.cmake` to detect new platform
2. Set `THEMIS_TARGET_PLATFORM` to new value
3. Add platform-specific validation in `validation/PlatformValidation.cmake`
4. If cross-compile, create toolchain file in `platforms/Toolchains/`

### Adding Architecture Optimizations
1. Update `ArchitectureOptimizations.cmake` with new architecture
2. Add appropriate compiler flags for the architecture
3. Document optimization level and compatibility

## 🚀 CI/CD INTEGRATION

### GitHub Actions
```yaml
name: Build ThemisDB
on: [push, pull_request]

jobs:
  build:
    strategy:
      matrix:
        os: [ubuntu-latest, windows-latest, macos-latest]
        edition: [MINIMAL, COMMUNITY, ENTERPRISE]
        
    runs-on: ${{ matrix.os }}
    
    steps:
      - uses: actions/checkout@v3
      
      - name: Configure
        run: |
          cmake -S . -B build \
            -DCMAKE_BUILD_TYPE=Release \
            -DTHEMIS_EDITION=${{ matrix.edition }}
      
      - name: Build
        run: cmake --build build --config Release -j4
      
      - name: Test
        run: ctest --test-dir build -C Release --output-on-failure
```

### Cross-Compile CI
```yaml
name: Cross-Compile
on: [push, pull_request]

jobs:
  cross-compile:
    runs-on: ubuntu-latest
    strategy:
      matrix:
        arch: [arm64, armv7]
        
    steps:
      - uses: actions/checkout@v3
      
      - name: Install Cross-Compiler
        run: |
          sudo apt-get update
          sudo apt-get install -y gcc-aarch64-linux-gnu g++-aarch64-linux-gnu \
                                  gcc-arm-linux-gnueabihf g++-arm-linux-gnueabihf
      
      - name: Configure
        run: |
          cmake -S . -B build-${{ matrix.arch }} \
            -DCMAKE_TOOLCHAIN_FILE=cmake/platforms/Toolchains/${{ matrix.arch }}-linux-gnu.cmake \
            -DTHEMIS_EDITION=COMMUNITY \
            -DCMAKE_BUILD_TYPE=Release
      
      - name: Build
        run: cmake --build build-${{ matrix.arch }} -j4
```

## 🆘 TROUBLESHOOTING

### Build Fails with Missing Dependencies
1. Ensure vcpkg is installed and configured
2. Check `vcpkg.json` for required packages
3. Run: `vcpkg install` to install dependencies
4. Set environment variable: `export VCPKG_ROOT=/path/to/vcpkg`

### Cross-Compile Fails
1. Verify cross-compiler is installed: `which aarch64-linux-gnu-gcc`
2. Check toolchain file path is correct
3. Ensure vcpkg triplet matches: `arm64-linux` for ARM64
4. Check sysroot path in toolchain file

### Features Not Enabled
1. Check edition constraints in `cmake/editions/`
2. Verify feature is not force-disabled by edition
3. Check validation rules in `cmake/validation/`
4. Use `-DTHEMIS_ENABLE_XXX=ON` to explicitly enable

### Platform Not Detected
1. Check `CMAKE_SYSTEM_PROCESSOR` value
2. Update `PlatformDetection.cmake` regex patterns
3. File issue for unsupported platform
