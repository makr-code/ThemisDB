# Audit Reports Directory

This directory contains generated audit and security scan reports from automated CI/CD workflows and manual security assessments.

## Directory Purpose

The `.audit-reports/` directory stores:
- SAST (Static Application Security Testing) reports
- DAST (Dynamic Application Security Testing) results
- Dependency vulnerability scans
- Container security scan reports
- Code coverage reports
- Compliance verification results

## Report Types

### SAST Reports
- `cppcheck-report.xml` - C++ static analysis results
- `clang-tidy-output.txt` - Clang-tidy linter results
- `gitleaks-report.json` - Secret scanning results

### DAST Reports
- `zap-report.html` - OWASP ZAP dynamic scan results
- `zap-report.json` - Machine-readable ZAP results

### Dependency Scans
- `trivy-scan.json` - Container vulnerability scan
- `dependency-check.xml` - Dependency vulnerability report

### Coverage Reports
- `coverage-report.html` - Code coverage visualization
- `coverage-summary.txt` - Coverage statistics

## Usage

### Generated by CI/CD
Reports are automatically generated by the `audit-check.yml` workflow on:
- Pull requests
- Release tags
- Manual workflow dispatches

### Local Generation
To generate reports locally:

```bash
# SAST with cppcheck
cppcheck --enable=all --xml --output-file=build/.audit-reports/cppcheck-report.xml src/ include/

# SAST with clang-tidy
cmake -DCMAKE_EXPORT_COMPILE_COMMANDS=ON -B build
clang-tidy -p build src/**/*.cpp > build/.audit-reports/clang-tidy-output.txt

# Secret scanning with gitleaks
docker run --rm -v $(pwd):/repo zricethezav/gitleaks:latest detect \
  --source /repo \
  --report-path /repo/build/.audit-reports/gitleaks-report.json

# Container scanning with Trivy
docker build -t themisdb:audit .
trivy image --format json --output build/.audit-reports/trivy-scan.json themisdb:audit

# Code coverage
cmake -DCMAKE_CXX_FLAGS="--coverage" -B build-coverage
cmake --build build-coverage
cd build-coverage && ctest
gcovr -r .. --html-details ../build/.audit-reports/coverage-report.html
```

## Report Retention

- **CI/CD Artifacts:** 90 days (GitHub Actions default)
- **Local Reports:** Not committed (excluded via .gitignore)
- **Archived Evidence:** Stored in `docs/audit-framework/evidence/v{version}/`

## Best Practices

1. **Review reports immediately** after generation
2. **Document findings** in audit tracking issue
3. **Archive significant reports** to evidence directory
4. **Never commit sensitive information**
5. **Use machine-readable formats** for automation

## Evidence Archival

For release audits, archive reports to evidence directory:

```bash
VERSION="v1.4.1"
mkdir -p docs/audit-framework/evidence/${VERSION}/scans/
cp build/.audit-reports/*.json docs/audit-framework/evidence/${VERSION}/scans/
cp build/.audit-reports/*.xml docs/audit-framework/evidence/${VERSION}/scans/
```
