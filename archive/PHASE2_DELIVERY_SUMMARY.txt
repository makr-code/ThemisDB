PROJECT OVERVIEW
================================================================================
Building on Phase 1 design contracts, Phase 2 delivers core hardening for the
ThemisDB Process Module with focus on:
  1. Concurrency safety using read-write locks (std::shared_mutex)
  2. Determinism with conflict detection and rollback semantics
  3. Enhanced diagnostics framework for incident triage
  4. Stress scenario hardening with graceful degradation

MODERN C++ PATTERNS APPLIED
================================================================================

✅ RAII (Resource Acquisition Is Initialization)
   - TransactionGuard ensures rollback on destruction
   - LinkOperationGuard ensures cleanup on failure
   - std::shared_lock/std::unique_lock auto-release
   - No manual lock management needed

✅ THREAD SAFETY
   - std::shared_mutex for read-write locking (not raw pthread)
   - std::shared_lock for concurrent readers
   - std::unique_lock for exclusive writers
   - std::atomic<uint64_t> for lock-free sequencing

✅ MODERN ERROR HANDLING
   - std::optional<T> for optional values
   - No exceptions in destructors
   - Structured exception safety via guards
   - Clear signaling of error conditions

✅ NO RAW POINTERS
   - All collections use STL containers
   - Shared ownership via std::shared_ptr
   - Exclusive ownership via std::unique_ptr or stack
   - Method parameters use references and string_view

✅ DELETED COPY OPERATIONS
   - Guard classes prevent accidental copies
   - Move operations deleted to prevent bypass
   - Compilation errors catch misuse early
