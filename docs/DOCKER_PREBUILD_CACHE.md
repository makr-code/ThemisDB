# Docker Prebuilt vcpkg Cache System

This guide explains how to use prebuilt vcpkg packages to dramatically speed up Docker builds for ThemisDB across multiple platforms (x64-windows, x64-linux, arm64-linux) in both debug and release configurations.

## Overview

The prebuilt cache system allows you to:
- **Build vcpkg packages once** on your development machine (Windows MSVC or Linux/WSL)
- **Mount them as read-only cache** in Docker containers
- **Speed up Docker builds** from 30 minutes → 2-5 minutes
- **Share prebuilt packages** with your team
- **Support multiple platforms** (x64-windows, x64-linux, arm64-linux)
- **Support both configurations** (debug and release)

## Performance Comparison

| Scenario | Without Prebuilt | With Prebuilt | Speedup |
|----------|------------------|---------------|---------|
| First Docker build | ~30 minutes | ~2-5 minutes | **6-15x faster** |
| Subsequent builds | ~15 minutes (binary cache) | ~30 seconds | **30x faster** |
| CI/CD pipeline | ~20 minutes | ~3 minutes | **6-7x faster** |

## Quick Start

### Step 1: Generate Prebuilt Cache

#### On Linux/WSL:
```bash
# Generate release packages (recommended)
./scripts/prebuild-vcpkg-linux.sh release

# Or generate both debug and release
./scripts/prebuild-vcpkg-linux.sh both
```

#### On Windows (MSVC):
```powershell
# Generate release packages (recommended)
.\scripts\prebuild-vcpkg-windows.ps1 -BuildType release

# Or generate both debug and release
.\scripts\prebuild-vcpkg-windows.ps1 -BuildType both
```

### Step 2: Use in Docker

#### Option A: docker-compose (Recommended)
```bash
docker-compose -f docker/docker-compose.prebuild.yml build
docker-compose -f docker/docker-compose.prebuild.yml up
```

#### Option B: docker build with BuildKit
```bash
export DOCKER_BUILDKIT=1

docker build \
  --build-arg ENABLE_VCPKG_CACHE=ON \
  --build-context prebuilt=./prebuilt-cache/x64-linux/release \
  -t themisdb:community .
```

## Directory Structure

The prebuilt cache is organized by platform and configuration:

```
ThemisDB/
├── prebuilt-cache/              # Generated by prebuild scripts
│   ├── x64-windows/             # Windows MSVC builds
│   │   ├── debug/
│   │   │   └── vcpkg_installed/
│   │   │       └── x64-windows/
│   │   │           ├── lib/     # Static libraries (.lib)
│   │   │           ├── bin/     # DLLs
│   │   │           ├── include/ # Headers
│   │   │           └── share/   # CMake configs
│   │   └── release/
│   │       └── vcpkg_installed/
│   ├── x64-linux/               # Linux x86_64 builds
│   │   ├── debug/
│   │   │   └── vcpkg_installed/
│   │   │       └── x64-linux/
│   │   │           ├── lib/     # Static/shared libraries (.a, .so)
│   │   │           ├── include/
│   │   │           └── share/
│   │   └── release/
│   │       └── vcpkg_installed/
│   └── arm64-linux/             # ARM64 Linux builds
│       ├── debug/
│       └── release/
├── scripts/
│   ├── prebuild-vcpkg-linux.sh    # Linux/WSL prebuild generator
│   └── prebuild-vcpkg-windows.ps1 # Windows prebuild generator
└── docker/
    └── docker-compose.prebuild.yml
```

## Detailed Usage

### Generating Prebuilt Cache

#### Linux/WSL Script Options

```bash
# Show help
./scripts/prebuild-vcpkg-linux.sh --help

# Generate release only (fastest)
./scripts/prebuild-vcpkg-linux.sh release

# Generate debug only
./scripts/prebuild-vcpkg-linux.sh debug

# Generate both debug and release
./scripts/prebuild-vcpkg-linux.sh both

# With specific edition
THEMIS_EDITION=MINIMAL ./scripts/prebuild-vcpkg-linux.sh release

# With custom triplet
VCPKG_TARGET_TRIPLET=arm64-linux ./scripts/prebuild-vcpkg-linux.sh release
```

#### Windows PowerShell Script Options

```powershell
# Show help
.\scripts\prebuild-vcpkg-windows.ps1 -Help

# Generate release only (fastest)
.\scripts\prebuild-vcpkg-windows.ps1 -BuildType release

# Generate debug only
.\scripts\prebuild-vcpkg-windows.ps1 -BuildType debug

# Generate both debug and release
.\scripts\prebuild-vcpkg-windows.ps1 -BuildType both

# With specific edition
.\scripts\prebuild-vcpkg-windows.ps1 -Edition MINIMAL -BuildType release

# With custom triplet
.\scripts\prebuild-vcpkg-windows.ps1 -Triplet x64-windows-static -BuildType release
```

### Using Prebuilt Cache in Docker

#### Method 1: docker-compose (Simplest)

The `docker/docker-compose.prebuild.yml` file is preconfigured to use prebuilt caches:

```bash
# Build all services with prebuilt cache
docker-compose -f docker/docker-compose.prebuild.yml build

# Build specific service
docker-compose -f docker/docker-compose.prebuild.yml build themisdb-community

# Start services
docker-compose -f docker/docker-compose.prebuild.yml up
```

#### Method 2: docker build (More Control)

```bash
# Enable BuildKit
export DOCKER_BUILDKIT=1

# Build with release prebuilt cache
docker build \
  --build-arg THEMIS_EDITION=COMMUNITY \
  --build-arg ENABLE_VCPKG_CACHE=ON \
  --build-context prebuilt=./prebuilt-cache/x64-linux/release \
  -t themisdb:community .

# Build with debug prebuilt cache
docker build \
  --build-arg THEMIS_EDITION=COMMUNITY \
  --build-arg ENABLE_VCPKG_CACHE=ON \
  --build-context prebuilt=./prebuilt-cache/x64-linux/debug \
  -t themisdb:community-debug .
```

#### Method 3: Manual Mount (Advanced)

```bash
docker run -it \
  -v $(pwd)/prebuilt-cache/x64-linux/release/vcpkg_installed:/vcpkg-prebuilt:ro \
  themisdb:builder \
  /bin/bash
```

```powershell
cd C:\path\to\ThemisDB
```

#### Step 2: Access from WSL
```bash
# In WSL
cd /mnt/c/path/to/ThemisDB

# Verify prebuilt cache
ls -lh prebuilt-cache/x64-windows/release/vcpkg_installed
```


#### Step 4: Use in Docker
```bash
docker-compose -f docker/docker-compose.prebuild.yml build
```

### Scenario 2: Build on Linux, Use in Docker

```bash
# Generate prebuilt cache
./scripts/prebuild-vcpkg-linux.sh release

# Use immediately in Docker
docker-compose -f docker/docker-compose.prebuild.yml build
```

## Sharing Prebuilt Cache with Team

### Option 1: Network Share

```bash
# Host machine: Share prebuilt cache
mkdir -p /shared/themisdb-prebuilts
cp -r prebuilt-cache/x64-linux/release /shared/themisdb-prebuilts/

# Team member: Use shared cache
ln -s /shared/themisdb-prebuilts/release prebuilt-cache/x64-linux/release
docker-compose -f docker/docker-compose.prebuild.yml build
```

### Option 2: Archive and Distribute

```bash
# Create archive
tar czf vcpkg-x64-linux-release-$(date +%Y%m%d).tar.gz \
  -C prebuilt-cache/x64-linux/release vcpkg_installed

# Team member: Extract
mkdir -p prebuilt-cache/x64-linux/release
tar xzf vcpkg-x64-linux-release-*.tar.gz \
  -C prebuilt-cache/x64-linux/release
```

### Option 3: Cloud Storage (S3, Azure Blob)

```bash
# Upload to S3
aws s3 cp prebuilt-cache/x64-linux/release/ \
  s3://company-bucket/themisdb-prebuilts/x64-linux/release/ \
  --recursive

# Team member: Download
aws s3 sync s3://company-bucket/themisdb-prebuilts/x64-linux/release/ \
  prebuilt-cache/x64-linux/release/
```

## Advanced Topics

### Multi-Platform Prebuilts

Generate prebuilts for multiple platforms:

```bash
# x64-linux
./scripts/prebuild-vcpkg-linux.sh release

# arm64-linux (requires ARM64 toolchain)
VCPKG_TARGET_TRIPLET=arm64-linux ./scripts/prebuild-vcpkg-linux.sh release

# x64-windows (on Windows)
.\scripts\prebuild-vcpkg-windows.ps1 -BuildType release
```

### CI/CD Integration

#### GitHub Actions Example

```yaml
name: Build with Prebuilt Cache

on: [push, pull_request]

jobs:
  build-docker:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      
      # Restore prebuilt cache from artifacts
      - name: Download prebuilt cache
        uses: actions/download-artifact@v3
        with:
          name: vcpkg-prebuilt-cache
          path: prebuilt-cache/
      
      # Build with prebuilt cache
      - name: Build Docker image
        run: |
          export DOCKER_BUILDKIT=1
          docker-compose -f docker/docker-compose.prebuild.yml build
      
      # Save prebuilt cache for next run
      - name: Upload prebuilt cache
        uses: actions/upload-artifact@v3
        with:
          name: vcpkg-prebuilt-cache
          path: prebuilt-cache/
          retention-days: 30
```

## Troubleshooting

### Problem: Prebuilt script fails with "vcpkg not found"

**Solution:**
```bash
# Set VCPKG_ROOT
export VCPKG_ROOT=/path/to/vcpkg

# Or bootstrap vcpkg
cd vcpkg && ./bootstrap-vcpkg.sh
```

### Problem: Docker build doesn't use prebuilt cache

**Solution:**
```bash
# Ensure ENABLE_VCPKG_CACHE=ON
docker build --build-arg ENABLE_VCPKG_CACHE=ON ...

# Verify prebuilt context is mounted
docker build --build-context prebuilt=./prebuilt-cache/x64-linux/release ...

# Check Dockerfile recognizes prebuilt mount
docker build --progress=plain ... 2>&1 | grep "Using pre-built"
```

### Problem: Platform mismatch

**Error:** `x64-windows` prebuilt used for Linux container

**Solution:**
```bash
# Ensure correct platform
# For Linux Docker: use x64-linux
./scripts/prebuild-vcpkg-linux.sh release

# For Windows Docker: use x64-windows  
.\scripts\prebuild-vcpkg-windows.ps1 -BuildType release
```

### Problem: Outdated prebuilt cache

**Solution:**
```bash
# Regenerate prebuilt cache
rm -rf prebuilt-cache/x64-linux/
./scripts/prebuild-vcpkg-linux.sh release
```

## Best Practices

1. **Regenerate monthly** - vcpkg packages update regularly
2. **Use release for production** - Debug packages are much larger
3. **Archive prebuilts** - Save time for CI/CD and team members
4. **Verify before sharing** - Test prebuilt cache works before distributing
5. **Document versions** - Tag prebuilt archives with date and vcpkg baseline
6. **Use BuildKit** - Required for `--build-context` feature
7. **Separate by platform** - Don't mix x64-windows and x64-linux prebuilts
