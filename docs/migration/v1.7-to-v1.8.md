# Migration Guide: v1.7.x → v1.8.0

**Release date:** April 2026  
**Type:** Minor release with three breaking changes  
**Effort:** Low–Medium (automated tools available for most changes)

---

## Overview

ThemisDB v1.8.0 ships Wire Protocol V2, Serializable Snapshot Isolation, SAGA Engine, Versioned API Routing (`/v1/` and `/v2/`), PredictivePrefetcher, GPU Erasure Coder, MySQL/MariaDB importer, and numerous bug fixes. Most changes are backward-compatible. Three areas require migration action:

1. **HTTP API — unversioned endpoint paths** now redirect (301) to `/v1/`
2. **StreamWriter compression** — zlib replaced by ZSTD
3. **CI workflow files** relocated to a new directory structure

---

## Breaking Changes

### BC-1: Unversioned HTTP Endpoints → `/v1/` Redirect

**Impact:** Client code calling `/query`, `/insert`, etc. will receive HTTP 301 redirects.

**Before (v1.7.x):**
```
POST /query
GET  /collections
POST /insert
```

**After (v1.8.0):**
```
POST /v1/query     ← stable, no redirect
GET  /v1/collections
POST /v1/insert
```

Unversioned paths like `/query` now return `301 Moved Permanently` pointing to `/v1/query`. Most HTTP clients follow redirects automatically. However, clients that:
- check response status codes strictly
- use custom HTTP stacks that don't follow redirects
- send `POST` or `PUT` requests (some clients downgrade to `GET` on 301)

...must update their base URL or use a redirect-following client.

**Migration:**

**Option A (recommended):** Update all client base URLs from `http://host:8768` to `http://host:8768/v1`.

```python
# Before
client = ThemisDBClient(base_url="http://localhost:8768")

# After
client = ThemisDBClient(base_url="http://localhost:8768/v1")
```

**Option B:** Use the official SDK ≥ v1.8.0, which automatically uses `/v1/` paths.

**Option C (temporary):** Pass `follow_redirects=True` in your HTTP client. This works but adds an extra round-trip and is not recommended for production.

---

### BC-2: StreamWriter Compression — zlib → ZSTD

**Impact:** Data written with `StreamWriter` in v1.7.x uses zlib compression. v1.8.0 uses ZSTD by default. You cannot read v1.8.0-compressed streams with v1.7.x tools.

**Affected components:**
- `StreamWriter` / `StreamReader`
- WAL segment files written after upgrade
- Backup files created by `BackupManager` after upgrade

**Migration:**

1. **Before upgrading:** Flush and checkpoint all active streams.
   ```bash
   themisdb-admin checkpoint --all-streams
   ```

2. **After upgrading:** Old zlib-compressed segments remain readable during the transition window. They are automatically decompressed and re-encoded on next compaction.

3. **Clients that read raw stream files:** Update to use `ZstdStreamDecompressor` (include `<utils/zstd_codec.h>`). The `THEMIS_HAS_ZSTD` CMake flag must be set.

4. **Rolling upgrade:** During a mixed-version cluster (v1.7.x + v1.8.0), configure v1.8.0 nodes with `compression.writer=zlib` temporarily:
   ```yaml
   # themisdb.yaml (temporary, remove after all nodes upgraded)
   storage:
     stream_writer:
       compression: zlib
   ```
   Remove this override after all nodes are on v1.8.0.

---

### BC-3: CI Workflow Files Relocated

**Impact:** Custom CI scripts that reference `.github/workflows/` directly by filename may break if they relied on the old single-directory flat structure.

**Before (v1.7.x):** All 138 workflow files in `.github/workflows/`.

**After (v1.8.0):** Workflows reorganised into 9 functional categories — see [`.github/WORKFLOW_REGISTRY.md`](../../.github/WORKFLOW_REGISTRY.md).

**Migration:**
- Update any scripts, badges, or external tools that reference specific workflow filenames by path.
- Check `.github/WORKFLOW_REGISTRY.md` for the new canonical locations.

## New Features (Action Required or Recommended)

### Serializable Snapshot Isolation (SSI)

Available as `IsolationLevel::SerializableSnapshot`. Opt-in per transaction:

```cpp
auto tx = db.beginTransaction(IsolationLevel::SerializableSnapshot);
```

No migration required. Existing transactions continue to use their current isolation level.

### SAGA Orchestration Engine

New `SAGAOrchestrator` for distributed compensation workflows. No migration required — existing 2PC transactions are unaffected.

### Versioned API Routes `/v2/`

`/v2/` routes introduce bulk NDJSON, Server-Sent Events (SSE), and async job submissions. These are additive; no migration required.

### PredictivePrefetcher

Enabled automatically in the cache layer. No configuration changes required. To tune:
```yaml
cache:
  predictive_prefetch:
    enabled: true
    model: markov        # markov | lru
    lookahead_depth: 3
```

## Step-by-Step Migration

### 1. Pre-migration checks

```bash
# Verify current version
themisdb --version

# Check all nodes healthy
themisdb-admin cluster status

# Backup everything
themisdb-admin backup create --label "pre-v1.8-upgrade" --full

# List active streams
themisdb-admin streams list --active
```

### 2. Flush active streams (BC-2)

```bash
themisdb-admin checkpoint --all-streams
themisdb-admin streams list --active  # Should be empty or minimal
```

### 3. Deploy v1.8.0 (rolling)

For multi-node clusters use a **rolling upgrade** (see [docs/migration/README.md](README.md) for the rolling upgrade pattern):

```bash
# Node 1
systemctl stop themisdb
apt install themisdb=1.8.0  # or equivalent
# If mixed-version window: add compression.writer=zlib to themisdb.yaml
systemctl start themisdb
themisdb-admin node health

# Repeat for Node 2, Node 3, ...
```

### 4. Update API clients (BC-1)

```bash
# Verify redirect behaviour before updating clients
curl -I http://localhost:8768/query
# Should return: HTTP/1.1 301 Moved Permanently → /v1/query

# After client update, verify against /v1/
curl -X POST http://localhost:8768/v1/query \
  -H 'Content-Type: application/json' \
  -d '{"aql": "SELECT 1"}'
```

### 5. Remove temporary compression override (BC-2)

After all cluster nodes are on v1.8.0:
```bash
# Remove compression.writer=zlib from themisdb.yaml
# Then rolling restart
themisdb-admin rolling-restart
```

### 6. Post-migration validation

```bash
# Run built-in health checks
themisdb-admin health --full

# Run integration tests
cmake --build build --target run_integration_tests

# Validate metrics
curl http://localhost:9090/metrics | grep themisdb_version
```

## Rollback Procedure

If you need to roll back to v1.7.x:

1. **Stop v1.8.0 services.**
2. **Restore the pre-upgrade backup** (`pre-v1.8-upgrade`).
3. **Reinstall v1.7.x packages.**
4. **Verify data integrity:** `themisdb-admin verify --full`
5. **Remove any `/v1/` URL prefixes** added during migration.
6. **File an issue** describing the problem: [GitHub Issues](https://github.com/makr-code/ThemisDB/issues)

> **Note:** If v1.8.0 has been running >24 hours and new ZSTD-compressed WAL segments exist, a full restore from the pre-upgrade backup is required. Partial rollback is not supported.

## Configuration Diff (v1.7 → v1.8)

```yaml
# New options in v1.8.0 (all optional)

storage:
  stream_writer:
    compression: zstd      # NEW default (was zlib)

cache:
  predictive_prefetch:
    enabled: true           # NEW
    model: markov
    lookahead_depth: 3

server:
  versioned_routing:
    enabled: true           # NEW, true by default
    redirect_unversioned: true
```
