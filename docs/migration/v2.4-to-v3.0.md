# Migration Guide: v2.4.x to v3.0.0

## Overview

This draft records the planned MAJOR API/ABI changes for host-side skill
delegation and the first delegated native executor. The target is v3.0.0;
release timing and final API freeze are not yet established. Track the change
through [breaking-change issue #8301](https://github.com/makr-code/ThemisDB/issues/8301).

Do not treat this guide as evidence that the feature is enabled by default or
that RAG is covered. The integration remains opt-in.

## Breaking Changes

- **Binary rebuild required:** `ToolRegistry` and `OrchestratorContext` public
  object layouts changed. `TSStore::QueryOptions` also gained a work-meter
  member, changing its layout.
- **Graph traversal ABI:** `GraphIndexManager::boundedBfs` gained a work-meter
  parameter. Existing source calls may use its default, but binaries compiled
  against the old signature must be rebuilt and relinked.
- **Root-context creation:** `SkillDelegationContext::createRoot` now requires
  a non-empty host-supplied permission authorizer. Existing callers must pass
  a callback bound to the authenticated principal and tenant; missing,
  denied, or standard-exception policy results fail closed.
- **New bounded decoder API:** `GorillaSIMDDecoder::decodeAtMost` is additive;
  existing `decodeAll` behavior and signature remain available.
- **Delegated execution is opt-in:** ordinary mode-authorized handlers remain
  on their existing path. Delegated handlers require `tool.invoke`, check
  resource-specific grants themselves, and account work against the shared
  context budget.

The changes do not provide physical storage-I/O admission or snapshot
isolation. Payload bytes are charged after storage retrieval and before
parsing/decoding. RAG remains outside the delegation integration.

## New Features

- `registerDelegatedAssetImpactAnalysisTool()` binds one graph ID, edge type,
  and metric. It requires exact `graph.read` and `timeseries.read` grants in
  addition to delegated `tool.invoke` dispatch.
- Graph adjacency/document work and TSStore raw/chunk/sample work are charged
  to the shared candidate/content budget. Budget exhaustion fails the request
  without partial analysis results; already accepted charges are not refunded.
- Metered compressed queries use bounded Gorilla decoding and fail rather than
  return an incomplete result.

## Deprecated Features

None introduced by this change.

## Step-by-Step Migration

1. **Inventory binary consumers.** Identify applications and plugins that
   include the changed LLM, graph, or time-series headers. Rebuild and relink
   them against the v3.0.0 libraries; do not mix old binaries with new
   libraries.
2. **Update delegation-root creation.** Supply a trusted
   `SkillDelegationContext::PermissionAuthorizer` that verifies every exact
   action/resource grant against the authenticated request's principal and
   tenant. Do not derive identity or grants from skill text, model output, or
   tool arguments.
3. **Choose the delegated path explicitly.** Register delegated handlers with
   `ToolRegistry::registerDelegatedTool()` and invoke them with the host-issued
   context. Keep mode allow/deny checks enabled and have each handler check
   its own resource grants before protected reads.
4. **Bind asset-impact sources.** Register the delegated executor with the
   caller-authorized graph, edge type, metric, and principal-scoped storage.
   Grant `graph.read` only for the bound graph ID and `timeseries.read` only
   for the bound metric.
5. **Set meaningful budgets.** Configure shared candidate and content-byte
   ceilings for the request. Content-byte metering starts after storage reads,
   so retain independent database I/O, timeout, and authorization controls.
6. **Keep non-delegated use unchanged where appropriate.** Existing
   mode-authorized registration and calls without a meter remain available;
   they are not constrained by `SkillDelegationContext`.

## Code Changes Required

Create a root context using the application's real authorization policy:

```cpp
const themis::llm::SkillDelegationContext::PermissionAuthorizer authorize =
    [&authenticatedRequest, &applicationPolicy](
        std::string_view principal,
        std::string_view tenant,
        const themis::llm::SkillPermission& permission) {
        return applicationPolicy.authorize(
            authenticatedRequest, principal, tenant, permission);
    };

auto context = themis::llm::SkillDelegationContext::createRoot(
    authenticatedPrincipal,
    authenticatedTenant,
    exactPermissions,
    expiry,
    requestBudget,
    authorize);
if (!context) {
    // Propagate the returned authorization/validation error.
}
```

The policy call above is application-specific; it must verify the supplied
identity against the authenticated request and must fail closed on policy
errors.

## Testing

Before shipping v3.0.0, configure and build the affected targets, then run the
focused CTest entries:

- `test_graph_bounded_bfs_GraphFocusedTests`
- `test_skill_registry_LlmFocusedTests`
- `test_ai_orchestrator_LlmFocusedTests`

The Gorilla decoder tests are part of the `themis_tests` GoogleTest
discovery; select the `GorillaSIMDTest.*` cases from CTest.
The tests should cover old non-metered behavior, exact resource-grant denial,
standard authorizer exceptions, candidate/content exhaustion, compressed
chunk decode limits, and no-partial-result behavior. These tests have been
added or updated, but build and CTest evidence is still pending.
