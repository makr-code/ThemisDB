# docs/reviews

## Zweck
`docs/reviews/` enthält formale Review-Artefakte (Fachreviews, Architektur-Reviews, Code-Review-Berichte).

## Pflegeverantwortung
- **Owner:** Review Leads / Architekturteam
- **Co-Owner:** Documentation Governance Maintainer

## Abgrenzung: Generiert vs. manuell
- **Manuell (hier):** reviewer-signierte Berichte und Zusammenfassungen
- **Generiert (nicht hier):** Roh-Scannergebnisse in `docs/_generated/`
- **Issue-Planung (nicht hier):** in `docs/issues/`

## Verbindliche Review- und QA-Kriterien
- `docs/DOCUMENTATION_REVIEW_GUIDELINES.md`
- `docs/PR_DOCUMENTATION_CHECKLIST.md`
- `docs/SYSTEMATISCHER_REVIEWPLAN.md`
- `docs/DOCUMENTATION_MERGE_PROTOCOL.md`

## Mindestinhalt eines Review-Artefakts
- Scope (Dateien/Bereiche)
- Prüfgrundlage (Checklisten/Runbook)
- Findings inkl. Prioritaet
- Entscheidung/Sign-off
- Verweis auf Folge-Issues (falls offen)
