================================================================================
RESEARCH: AGENTIC AI SELF-AWARENESS IN THEMISDB
================================================================================

Datum: 11. Januar 2026
Issue: "Gibt es eine Form der self-awareness der Themis (+llama.cpp) die 
       kommunizieren kann welche Daten in der DB gespeichert sind und wie 
       die benutzt werden können (Agentic AI)"

================================================================================
ZUSAMMENFASSUNG
================================================================================

Diese Research-Initiative analysiert, ob und wie ThemisDB "selbstbewusst" sein 
kann - also Fragen über sich selbst beantworten kann wie:
- "Was kannst du?"
- "Wo sind die Daten?"
- "Wie sind die Daten aufgebaut?"
- "Was ist deine Aufgabe?"

ERGEBNIS: ✅ MÖGLICH, aber nicht vollständig implementiert

================================================================================
WAS EXISTIERT BEREITS
================================================================================

✅ Model Context Protocol (MCP) Server (v1.3.0)
   - Vollständige Transport-Layer (stdio, SSE, WebSocket)
   - Tool/Resource/Prompt-Architektur vorhanden
   - JSON-RPC Protocol-Handling funktioniert

✅ LLM Integration (v1.3.0+, optional mit -DTHEMIS_ENABLE_LLM=ON)
   - llama.cpp vollständig integriert
   - Grammar-Constrained Generation
   - ReAct Agent Grammar implementiert
   - Vision Support, Flash Attention (v1.4.0-alpha)

✅ Secondary Index System
   - 7 verschiedene Index-Typen
   - Introspection-Methods im C++ Code vorhanden

✅ Multi-Protocol Support
   - HTTP/REST, gRPC, PostgreSQL Wire, MCP, GraphQL

================================================================================
WAS FEHLT
================================================================================

❌ Vollständige Schema-Discovery
   - MCP get_schema ist nur Stub (gibt leere Arrays zurück)
   - Keine zentrale Schema-Registry
   - Kein REST /schema Endpoint

❌ Natural Language Self-Awareness
   - LLM kann nicht über DB-Struktur antworten
   - Keine System-Prompts für Self-Awareness
   - Fehlender Context für "Was kannst du?"-Fragen

❌ Capabilities Endpoint
   - Keine /api/v1/capabilities REST API
   - DB kann ihre Features nicht selbst beschreiben

HAUPTPROBLEM: Die MCP-Integration ist "minimal" - kritische Komponenten 
              sind nur als Placeholders implementiert

================================================================================
EMPFOHLENE LÖSUNG
================================================================================

PHASE 1: Schema Manager (Priorität: HOCH, ~500 LOC)
  - SchemaManager Klasse erstellen
  - RocksDB Key-Scanning für Table-Discovery
  - Property-Type Detection
  - Index-Metadaten-Sammlung

PHASE 2: REST API Endpoints (Priorität: HOCH, ~300 LOC)
  - GET /api/v1/schema - Vollständiges Schema
  - GET /api/v1/capabilities - Datenbank-Fähigkeiten
  - GET /api/v1/schema/tables/:name - Einzelne Tabelle

PHASE 3: MCP Full Integration (Priorität: HOCH, ~200 LOC)
  - toolGetSchema() mit echten Daten
  - resourceSchema() auf SchemaManager umstellen
  - Echte Statistiken statt Hardcoded 0

PHASE 4: Natural Language Q&A (Priorität: MITTEL, ~400 LOC)
  - System-Prompts für Self-Awareness
  - LLM Context-Injection (Schema, Stats)
  - toolIntrospectDatabase() implementieren

GESAMT: ~1400 LOC neuer Code, 3-4 Sprints
