```

3. Verbesserung  (2-4h)       → Sprache, Code, Diagramme
4. Design        (30-60 min)  → Layout-Standards
5. Validierung   (1-2h)       → Testen, Prüfen
6. Review        (30-60 min)  → Feedback einarbeiten
7. Dokumentation (15-30 min)  → TODO aktualisieren, Commit
──────────────────────────────────────────────────────
Gesamt: 5-12 Stunden pro Kapitel
```

## ❓ FAQ

### Warum reverse order (41→00)?
Von Praxis zu Theorie arbeiten. Hands-on-Kapitel sind leichter zu verbessern als fundamentale Architektur-Kapitel.

### Warum verbessern statt neu schreiben?
- ✅ Bestehendes Wissen erhalten
- ✅ Struktur bewahren
- ✅ Keine Duplikate
- ✅ Weniger Aufwand

### Wie viel Zeit pro Kapitel?
5-12 Stunden je nach Komplexität:
- Einfach (Installation): 5-6h
- Mittel (Features): 7-9h
- Komplex (Architektur): 10-12h
- Sehr komplex (Query Optimization): 12-15h

### Was, wenn ich Fehler im Workflow finde?
Lessons Learned dokumentieren in CHAPTER_IMPROVEMENT_ROADMAP.md und Workflow anpassen.
