## 🚀 Hauptfeatures

### RPC Plugin Framework
Einführung eines flexiblen, plugin-basierten RPC (Remote Procedure Call) Frameworks, das ThemisDB ermöglicht, verschiedene RPC-Protokolle zu unterstützen.

**Kernkomponenten:**
- ✅ RPC Plugin Interface (`include/plugins/rpc_plugin_interface.h`)
- ✅ RPC Service Implementation (`src/server/rpc/rpc_service_impl.cpp`)
- ✅ Protobuf Definitions für Inter-Shard Kommunikation (`proto/sharding/shard_rpc.proto`)
- ✅ gRPC Plugin Implementation (`plugins/rpc/grpc/`)
- ✅ Umfassende Dokumentation

**Unterstützte Protokolle:**
- ✅ **gRPC** - High-performance, HTTP/2-basiert, mit native mTLS Support
- 🔄 **Apache Thrift** - Cross-language RPC Framework (v1.3.2)
- 🔄 **JSON-RPC 2.0** - Web-friendly, einfach zu nutzen (v1.3.2)
- ✅ **Wire Protocol v1** - Bestehendes ThemisDB Custom Protocol

### Enhanced Inter-Shard Communication ⭐ NEU

**RocksDB Snapshot Transfer:**
- Snapshot-basierter Bulk-Transfer für große Shards (>10 GB)
- 10-20x schneller als Record-by-Record Migration
- Zstd Compression (Level 9) für 4-5x Datenreduktion
- Chunked Transfer mit CRC32 Checksums

**Blob Transfer für LoRA Adapters:**
- Optimiert für große Binärdateien (LLM-Adapter, Modelle)
- Typische Größe: 100 MB - 10 GB
- High Compression (3-6x mit Zstd)
- Resume Support bei Netzwerkunterbrechungen

**Compression & Chunking:**
- Konfigurierbare Chunk-Größen (1-100 MB)
- Multiple Algorithms: LZ4 (schnell), Zstd (effizient), Snappy
- Per-Chunk Checksums: CRC32, SHA256, XXH64
- End-to-End Integrity Verification

## 🔒 Inter-Shard Communication mit mTLS

### Sichere Shard-zu-Shard Kommunikation
Integration des RPC Frameworks mit der bestehenden mTLS-Infrastruktur für sichere, authentifizierte Kommunikation zwischen Shards.

**Features:**
- ✅ Mutual TLS (mTLS) für alle Inter-Shard RPC-Aufrufe
- ✅ Zertifikat-basierte Shard-Authentifizierung
- ✅ PKI-Integration mit Custom X.509 Extensions
- ✅ Capability-based Access Control über Zertifikate
- ✅ CRL (Certificate Revocation List) Support

**Performance-Vorteile:**
- 🚀 6-8x schneller als HTTP/REST
- 🚀 5-10x kleinere Payloads (Protobuf vs JSON)
- 🚀 Bidirectional Streaming für Bulk-Operationen
- 🚀 HTTP/2 Multiplexing

**Dokumentation:**
- [RPC Plugin Architecture](../docs/plugins/RPC_PLUGIN_ARCHITECTURE.md)
- [RPC mTLS Inter-Shard Communication](../docs/plugins/RPC_MTLS_INTER_SHARD.md)

### RPC Plugin Interface

**Neue Enums:**
```cpp
namespace themis::plugins::rpc {
    enum class RPCProtocol {
        GRPC, THRIFT, JSON_RPC, MSGPACK_RPC, 
        WIRE_PROTOCOL, CUSTOM
    };
    
    enum class RPCErrorCode {
        OK, AUTHENTICATION_FAILED, AUTHORIZATION_FAILED,
        ENTITY_NOT_FOUND, INVALID_QUERY, INTERNAL_ERROR,
        METHOD_NOT_FOUND, RATE_LIMIT_EXCEEDED, ...

}
```

**Neue Interfaces:**
```cpp
class IRPCServer {
    virtual RPCProtocol getProtocol() const = 0;
    virtual bool initialize(const RPCServerConfig& config) = 0;
    virtual bool start() = 0;
    virtual void stop() = 0;
    virtual bool isRunning() const = 0;
    virtual RPCServerStats getStats() const = 0;
    virtual void registerService(void* service_impl) = 0;
};

class IRPCPlugin : public IThemisPlugin {
    virtual std::unique_ptr<IRPCServer> createServer() = 0;
    virtual RPCProtocol getProtocol() const = 0;
    virtual uint16_t getDefaultPort() const = 0;
};
```

### Inter-Shard RPC Service (Protobuf)

**Neue gRPC Services:**
```protobuf
service ShardService {
    // Replication
    rpc ReplicateData(ReplicateRequest) returns (ReplicateResponse);
    rpc ReplicateDataStream(stream ReplicateChunk) returns (ReplicateResponse);
    
    // Distributed Transactions
    rpc PrepareTransaction(PrepareRequest) returns (PrepareResponse);
    rpc CommitTransaction(CommitRequest) returns (CommitResponse);
    rpc AbortTransaction(AbortRequest) returns (AbortResponse);
    
    // Data Migration
    rpc MigrateData(MigrateRequest) returns (stream MigrateChunk);
    
    // Status & Monitoring
    rpc GetShardStatus(StatusRequest) returns (StatusResponse);
    rpc HealthCheck(HealthRequest) returns (HealthResponse);
    
    // Gossip Protocol
    rpc GossipExchange(GossipMessage) returns (GossipMessage);
}
```

## 🔧 Konfiguration

### RPC Server Konfiguration

**Neue Konfigurationsoptionen in `config.yaml`:**

```yaml
rpc:
  # Enable RPC framework
  enabled: true
  
  # Plugin directory
  plugin_directory: "./plugins/rpc"
  
  # Auto-load RPC plugins
  auto_load: true
  
  # RPC servers configuration
  servers:
    # gRPC Server (für Inter-Shard und Client-Kommunikation)
    grpc:
      enabled: true
      host: "0.0.0.0"
      port: 50051
      
      # mTLS Configuration
      tls:
        enabled: true
        cert_path: "./certs/server.crt"
        key_path: "./certs/server.key"
        ca_cert_path: "./certs/ca.crt"
        verify_peer: true
        verify_hostname: true
      
      # Connection settings
      max_connections: 1000
      thread_pool_size: 8
      connection_timeout_ms: 5000
      request_timeout_ms: 30000
    
    # Thrift Server
    thrift:
      enabled: false
      host: "0.0.0.0"
      port: 9090
    
    # JSON-RPC Server
    jsonrpc:
      enabled: false
      host: "0.0.0.0"
      port: 8081
  
  # Authentication
  auth:
    required: true
    token_expiry: 3600  # seconds
  
  # Rate Limiting
  rate_limit:
    enabled: true
    requests_per_second: 1000
    burst_size: 100

# Inter-Shard RPC Configuration
sharding:
  communication:
    # Use RPC for inter-shard communication
    rpc_enabled: true
    rpc_fallback_to_http: true
    
    rpc:
      protocol: "grpc"
      listen_address: "0.0.0.0:50051"
      
      mtls:
        enabled: true
        cert_path: "/etc/themis/certs/shard.crt"
        key_path: "/etc/themis/certs/shard.key"
        ca_cert_path: "/etc/themis/certs/ca.crt"
        crl_path: "/etc/themis/certs/crl.pem"
        verify_peer: true
        verify_hostname: true
```

## 📊 Performance Benchmarks

### Erwartete Performance-Verbesserungen

**Client-Server RPC (gRPC vs HTTP/REST):**

| Metrik | HTTP/REST | gRPC | Verbesserung |
|--------|-----------|------|--------------|
| GET Latency (p50) | 1.5 ms | 0.3 ms | **5x schneller** |
| GET Latency (p99) | 5 ms | 1 ms | **5x schneller** |
| Throughput | 1,000 ops/s | 10,000 ops/s | **10x höher** |
| Payload Size (1KB) | 1.5 KB | 1.1 KB | **27% kleiner** |

**Inter-Shard RPC (gRPC vs HTTP/mTLS):**

| Metrik | HTTP/mTLS | gRPC/mTLS | Verbesserung |
|--------|-----------|-----------|--------------|
| Latency (p50) | 5.0 ms | 0.8 ms | **6.25x schneller** |
| Latency (p99) | 15.0 ms | 2.5 ms | **6x schneller** |
| Throughput | 2,000 ops/s | 15,000 ops/s | **7.5x höher** |
| Bulk Replication (10k entities) | ~15 sec | ~2 sec | **7.5x schneller** |

## 🔄 Migration & Kompatibilität

### Backward Compatibility

- ✅ **Vollständig rückwärtskompatibel** - Bestehende HTTP/REST API bleibt unverändert
- ✅ **Parallelbetrieb** - RPC und HTTP können gleichzeitig laufen
- ✅ **Feature Flags** - RPC kann pro Feature aktiviert/deaktiviert werden
- ✅ **Graceful Fallback** - Automatischer Fallback zu HTTP bei RPC-Fehlern

### Migration Path

**Phase 1: Deployment (v1.3.0)**
- RPC Framework wird deployed, ist aber standardmäßig deaktiviert
- Dokumentation und Beispiele verfügbar

**Phase 2: Opt-In (v1.3.1)**
- RPC kann per Feature-Flag aktiviert werden
- Monitoring und Metriken werden gesammelt

**Phase 3: Default Enabled (v1.4.0)**
- RPC wird standardmäßig aktiviert
- HTTP bleibt als Fallback verfügbar

**Phase 4: Deprecation (v2.0.0)**
- HTTP/REST wird als deprecated markiert
- Migration zu RPC wird empfohlen

## 📝 Upgrade Notes

### Von v1.2.x auf v1.3.0

**Keine Breaking Changes!**

Diese Release ist vollständig rückwärtskompatibel. RPC Framework ist ein neues Feature und beeinträchtigt keine bestehenden Funktionen.

**Optional: RPC aktivieren**

1. Konfiguration aktualisieren:
   ```yaml
   # config.yaml
   rpc:
     enabled: true
     servers:
       grpc:
         enabled: true
   ```

2. Server neu starten:
   ```bash
   systemctl restart themisdb
   ```

3. Verifizieren:
   ```bash
   # Check RPC server is listening
   netstat -tlnp | grep 50051
   ```

**Neue Dependencies (Optional - nur für gRPC):**

```bash
# Ubuntu/Debian
sudo apt install libgrpc++-dev libprotobuf-dev protobuf-compiler-grpc

# macOS
brew install grpc protobuf

# vcpkg
vcpkg install grpc protobuf
```

**CMake Build Flags:**

```bash
cmake .. -DTHEMIS_BUILD_RPC_FRAMEWORK=ON \
         -DTHEMIS_BUILD_RPC_GRPC_PLUGIN=ON

make
```
