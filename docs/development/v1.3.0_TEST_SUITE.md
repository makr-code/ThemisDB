# v1.3.0 Test Suite Documentation

## Overview

Comprehensive test suite for all v1.3.0 features including unit tests, integration tests, and performance benchmarks.

## Test Files Created

### 1. Embedding Cache Tests (`test_embedding_cache.cpp`)

**Test Categories:**
- Basic functionality (store, retrieve, similarity matching)
- LRU eviction behavior
- TTL expiration
- Hit/miss statistics
- Thread safety
- Edge cases (empty embeddings, large embeddings)
- Metric-aware similarity (cosine, dot product, L2)

**Test Count:** 15+ test cases

**Key Tests:**
- `StoreAndRetrieve`: Basic cache operations
- `SimilarityMatch`: Fuzzy matching with similarity threshold
- `LRUEviction`: Verify LRU replacement policy
- `TTLExpiration`: Time-based cache invalidation
- `ConcurrentAccess`: Thread safety validation
- `CostSavings`: Economic value tracking

### 2. Recursive CTE Tests (`test_recursive_ctes.cpp`)

**Test Categories:**
- Simple org hierarchy traversal
- Limited depth recursion
- Cycle detection
- Maximum iteration/result size limits
- Transitive closure
- Bill of materials (BOM) queries
- UNION semantics
- Edge cases (empty anchor, single iteration)

**Test Count:** 12+ test cases

**Key Tests:**
- `SimpleOrgHierarchy`: Basic recursive traversal
- `CycleDetection`: Prevent infinite loops
- `MaxIterationsLimit`: Configurable depth limit
- `TransitiveClosure`: Graph reachability
- `UnionAllSemantics`: Proper result combination

### 3. Distributed Transaction Tests (`test_distributed_transactions.cpp`)

**Test Categories:**
- Basic transaction lifecycle
- Two-phase commit (2PC) protocol
- Snapshot reads
- RPC client retry logic
- Concurrent transactions
- MVCC integration
- Error handling
- Performance tests

**Test Count:** 18+ test cases

**Key Tests:**
- `TwoPhaseCommitSuccess`: Happy path 2PC
- `TwoPhaseCommitAbort`: Rollback on failure
- `SnapshotConsistency`: Consistent reads across shards
- `RPCRetry`: Network failure handling
- `ConcurrentTransactions`: Multi-threaded safety
- `HighThroughput`: 100+ txn/sec validation

## Benchmark Suite (`bench_v1_3_0_features.cpp`)

### Embedding Cache Benchmarks

**Benchmarks:**
- `BM_EmbeddingCache_Store`: Store performance across embedding dimensions (384, 768, 1536, 3072)
- `BM_EmbeddingCache_Query_Hit`: Cache hit latency
- `BM_EmbeddingCache_Query_Miss`: Cache miss latency + HNSW search
- `BM_EmbeddingCache_CostSavings`: Economic impact measurement

**Metrics:**
- Operations per second
- Latency (mean, p50, p95, p99)
- Hit rate
- Cost savings

### Hybrid Search Benchmarks

**Benchmarks:**
- `BM_HybridSearch_RRF`: Reciprocal Rank Fusion performance
- `BM_HybridSearch_LinearCombination`: Linear combination fusion
- `BM_HybridSearch_VaryingWeights`: Impact of BM25/vector weight ratios (0/100, 25/75, 50/50, 75/25, 100/0)

**Metrics:**
- Search latency
- Recall@10, Recall@50
- Fusion overhead

### CTE Benchmarks

**Benchmarks:**
- `BM_CTE_NonRecursive_Simple`: Non-recursive CTE execution (1, 5, 10, 20 CTEs)
- `BM_CTE_Recursive_Depth`: Recursive depth impact (10, 50, 100, 1000 iterations)
- `BM_CTE_CycleDetection`: Cycle detection overhead (100, 1K, 10K nodes)
- `BM_Subquery_EXISTS_WithLIMIT1`: LIMIT 1 optimization (100, 1K, 10K, 100K rows)
- `BM_Subquery_EXISTS_WithoutLIMIT1`: Baseline without optimization

**Metrics:**
- Execution time per CTE
- Iterations per second
- Optimization speedup (LIMIT 1: 10-1000x faster)

### Distributed Transaction Benchmarks

**Benchmarks:**
- `BM_DistributedTxn_2PC_Latency`: 2PC latency vs shard count (2, 4, 8, 16 shards)
- `BM_DistributedTxn_Throughput`: Transaction throughput
- `BM_DistributedTxn_SnapshotRead`: Snapshot read latency
- `BM_ShardRPC_RoundTrip`: RPC round-trip time

**Metrics:**
- Commit latency (2PC overhead)
- Transactions per second
- Scalability (latency vs shard count)

### Combined Feature Benchmarks

**Benchmarks:**
- `BM_Combined_LLM_RAG_Pipeline`: End-to-end LLM RAG workflow
  - Embedding cache check
  - Hybrid search on miss
  - Cache population

**Metrics:**
- End-to-end latency
- Cache hit rate over time
- Cost savings

## Running Tests

### Build Tests
```bash
cd /home/runner/work/ThemisDB/ThemisDB
mkdir -p build
cd build
cmake .. -DBUILD_TESTS=ON
make -j$(nproc)
```

### Run All Tests
```bash
ctest --output-on-failure
```

### Run Specific Test Suites
```bash
# Embedding Cache Tests
./tests/test_embedding_cache

# Recursive CTE Tests
./tests/test_recursive_ctes

# Distributed Transaction Tests
./tests/test_distributed_transactions
```

### Run with GTest Filters
```bash
# Run only concurrency tests
./tests/test_embedding_cache --gtest_filter="*Concurrent*"

# Run only recursive tests
./tests/test_recursive_ctes --gtest_filter="*Recursive*"
```

## Expected Results

### Embedding Cache
- **Store:** 10K-100K ops/sec (depending on dimension)
- **Query Hit:** 50K-500K ops/sec (HNSW O(log N))
- **Query Miss:** 1K-10K ops/sec (brute force fallback)
- **Hit Rate:** 70-90% (typical LLM workload)
- **Cost Savings:** ~$0.0001 per hit

### Hybrid Search
- **RRF Latency:** 10-50ms (depending on index size)
- **Recall@10:** 85%+ (with balanced weights)
- **Fusion Overhead:** <5ms

### CTE Performance
- **Non-Recursive:** <1ms per CTE (simple queries)
- **Recursive:** 1-100ms (depending on depth and branching factor)
- **LIMIT 1 Optimization:** 10-1000x speedup for EXISTS queries

### Distributed Transactions
- **2PC Latency:** 10-50ms (2 shards), 20-100ms (16 shards)
- **Throughput:** 100-1000 txn/sec (single-node)
- **Snapshot Read:** 5-20ms per shard
- **Scalability:** Near-linear with shard count (parallel RPCs)
