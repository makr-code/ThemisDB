## The 3 Implementation Patterns

### Pattern 1: Resource-Holding Classes (18 gaps)
Used in: LLM, Query, GPU modules
- Explicit move constructor/assignment
- Smart pointer ownership transfer
- noexcept specifications
- Example: multi_lora_manager, gpu_kernel_manager

### Pattern 2: Non-Moveable Classes (16 gaps)
Used in: Query, Cache modules
- Deleted move operations
- Prevents threading bugs
- Compile-time safety
- Example: semantic_cache, cache_manager (with mutex)

### Pattern 3: Return Value Optimization (14 gaps)
Used in: Storage module
- Move-enabled return types
- Zero-copy semantics
- Backward compatible
- Example: encrypt_field, decrypt_field returns
