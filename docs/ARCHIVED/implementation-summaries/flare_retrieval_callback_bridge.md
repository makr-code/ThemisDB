## Overview

The **FLARE Retrieval-Callback Bridge** wires the
[`KnowledgeGapDetector`](../include/rag/knowledge_gap_detector.h) FLARE
active-retrieval loop to a live
[`VectorIndexManager`](../include/index/vector_index.h) instance.

Before this bridge, `performDynamicRetrieval()` always returned an empty
document list, making the FLARE loop a no-op even when
`enable_flare = true`.  The bridge provides:

- A strongly-typed `RetrievalCallback` function signature that any retrieval
  back-end can implement.
- `KnowledgeGapDetector::setRetrievalCallback()` to register the function.
- `LLMApiHandler::setVectorIndex()` to wire the full pipeline in the HTTP
  server with a single call.

### What is FLARE?

FLARE (**F**orward-**L**ooking **A**ctive **RE**trieval) is an iterative
retrieval strategy (Jiang et al., 2023) that monitors generation confidence
sentence-by-sentence and fetches additional context when confidence drops
below a threshold.  ThemisDB's implementation generalises this into the
`detectWithActiveRetrieval()` method of `KnowledgeGapDetector`.

## Architecture

```
 ┌──────────────────────────────────────────────────────────────────┐
 │  LLMApiHandler::handleRAG()                                      │
 │                                                                  │
 │  1. embed(query) ──▶ VectorIndexManager::searchKnn()            │
 │  2. convertToRetrievedDocuments()                                │
 │  3. RAGContext::documents populated                              │
 │  4. LLMPluginManager::generateRAG()                              │
 └──────────────────────────────────────────────────────────────────┘
                     │ optional gap detection
                     ▼
 ┌──────────────────────────────────────────────────────────────────┐
 │  KnowledgeGapDetector::detectWithActiveRetrieval()               │
 │                                                                  │
 │  while round < max_retrieval_rounds:                             │
 │    coverage = calculateQueryCoverage(query, docs)                │
 │    if coverage >= threshold: DONE                                │
 │    missing = findMissingAspects(query, docs)                     │
 │    reformulated = reformulateQuery(query, missing[0])            │
 │    new_docs = performDynamicRetrieval(reformulated)  ◀── bridge  │
 │    docs += deduplicate(new_docs)                                 │
 └──────────────────────────────────────────────────────────────────┘
                     │
                     ▼
 ┌──────────────────────────────────────────────────────────────────┐
 │  RetrievalCallback fn (user-supplied)                            │
 │                                                                  │
 │  [&vec_mgr, &db](const std::string& q, size_t k)                │
 │      → auto emb = embed(q)                                       │
 │        auto [st, hits] = vec_mgr.searchKnn(emb, k)              │
 │        return convertToRetrievedDocuments(hits, db)              │
 └──────────────────────────────────────────────────────────────────┘
```

## API Reference

### `RetrievalCallback` type

```cpp
// include/rag/knowledge_gap_detector.h
namespace themis::rag::knowledge_gap {

using RetrievalCallback =
    std::function<std::vector<RetrievedDocument>(const std::string& query,
                                                 size_t k)>;
}
```

| Parameter | Type | Description |
|-----------|------|-------------|
| `query`   | `const std::string&` | Reformulated sub-query generated by the FLARE loop |
| `k`       | `size_t` | Maximum number of documents to return; derived from `KnowledgeGapConfig::min_documents` |
| returns   | `std::vector<RetrievedDocument>` | Retrieved documents; **empty vector** signals no more results and stops the loop early |

The callback is invoked sequentially from a single thread and must be
thread-safe with respect to its captured state only (no re-entrancy
requirement).  Exceptions thrown by the callback are caught internally and
treated as an empty result.

---

### `KnowledgeGapDetector::setRetrievalCallback()`

```cpp
// include/rag/knowledge_gap_detector.h
void setRetrievalCallback(RetrievalCallback fn);
```

Stores `fn` in `Impl::retrieval_fn`.  Pass a default-constructed (empty)
`std::function` to detach the callback and disable FLARE dynamic retrieval.
Calling this method does **not** automatically enable FLARE; set
`KnowledgeGapConfig::enable_flare = true` first.

---

### `LLMApiHandler::setVectorIndex()`

```cpp
// include/server/llm_api_handler.h
void setVectorIndex(VectorIndexManager* vim, RocksDBWrapper* db);
```

| Parameter | Description |
|-----------|-------------|
| `vim`     | Non-owning pointer to a `VectorIndexManager` (already initialised). Pass `nullptr` to detach. |
| `db`      | Non-owning pointer to the `RocksDBWrapper` used to resolve entity content for `convertToRetrievedDocuments()`. |

When set, `handleRAG()`:

1. Calls `LLMPluginManager::embed(query)` to obtain a float embedding.
2. Calls `vim->searchKnn(embedding, top_k)`.
3. Converts results via `rag::convertToRetrievedDocuments(results, *db, Metric::COSINE)`.
4. Populates `RAGContext::documents` before calling `generateRAG()`.

Embed/search failures are **non-fatal**: the handler logs a `THEMIS_DEBUG`
message and proceeds with an empty context (same behaviour as without
`setVectorIndex()`).

## Quick-Start Examples

### 1 — Minimal standalone FLARE detector

```cpp
#include "rag/knowledge_gap_detector.h"
#include "rag/rag_integration_helpers.h"
#include "index/vector_index.h"
#include "storage/rocksdb_wrapper.h"

using namespace themis::rag::knowledge_gap;

// Setup
RocksDBWrapper db(config);
VectorIndexManager vec_mgr(db);
vec_mgr.init("documents", 1536);

auto embed_fn = [&](const std::string& text) -> std::vector<float> {
    return your_llm_plugin.embed(text);
};

// Create FLARE-enabled detector
KnowledgeGapConfig cfg;
cfg.enable_flare          = true;
cfg.max_retrieval_rounds  = 3;
cfg.flare_confidence_threshold = 0.5;
auto detector = KnowledgeGapDetector(cfg);

// Wire the retrieval callback
detector.setRetrievalCallback(
    [&](const std::string& q, size_t k) -> std::vector<RetrievedDocument> {
        auto emb = embed_fn(q);
        if (emb.empty()) return {};
        auto [st, hits] = vec_mgr.searchKnn(emb, k);
        if (!st.ok) return {};
        return rag::convertToRetrievedDocuments(hits, db);
    });

// Run FLARE active retrieval
std::vector<RetrievedDocument> docs = initial_docs;
auto result = detector.detectWithActiveRetrieval("What is ACID compliance?", docs);
// docs now contains the augmented document set
// result.gap_detected, result.explanation, result.recommendation
```

### 2 — HTTP server wiring via `LLMApiHandler`

```cpp
#include "server/llm_api_handler.h"
#include "llm/llm_plugin_manager.h"
#include "index/vector_index.h"
#include "storage/rocksdb_wrapper.h"

// Existing server components
auto plugin_mgr = std::make_shared<themis::llm::LLMPluginManager>(/* ... */);
themis::server::LLMApiHandler handler(plugin_mgr);

// Wire vector index (non-owning; handler must not outlive these objects)
handler.setVectorIndex(&vector_index_mgr, &rocksdb);

// Now POST /api/v1/llm/rag will perform real vector search:
// embed(query) → searchKnn(top_k) → convertToRetrievedDocuments → generateRAG
```

### 3 — Factory + callback (production-ready)

```cpp
auto detector = KnowledgeGapDetectorFactory::createProductionReady();
// enable_flare=true is already set; wire the callback:
detector->setRetrievalCallback(
    [&](const std::string& q, size_t k) {
        auto emb = llm.embed(q);
        auto [st, hits] = vec_mgr.searchKnn(emb, k);
        return rag::convertToRetrievedDocuments(hits, db);
    });
```

## Configuration Reference

Relevant fields in `KnowledgeGapConfig` (see `include/rag/knowledge_gap_detector.h`):

| Field | Type | Default | Effect |
|-------|------|---------|--------|
| `enable_flare` | `bool` | `true` *(production factory)* | Activates the FLARE loop in `detectWithActiveRetrieval()`. Must be `true` for the callback to be invoked. |
| `max_retrieval_rounds` | `size_t` | `3` | Maximum number of re-retrieval iterations. The callback is called at most this many times. |
| `flare_confidence_threshold` | `double` | `0.5` | Sentence-level confidence below which the loop triggers re-retrieval. |
| `coverage_threshold` | `double` | `0.8` | Minimum query-coverage score to consider retrieval complete. |
| `similarity_threshold` | `double` | `0.75` | Minimum average document similarity score. |
| `min_documents` | `size_t` | `3` | Drives the `k` value passed to `RetrievalCallback`. |

## Behaviour Guarantees

| Scenario | Behaviour |
|----------|-----------|
| `enable_flare = false` | `detectWithActiveRetrieval()` immediately returns `detectPreGeneration()` result; callback is **never** called. |
| No callback set | `performDynamicRetrieval()` returns `{}` silently; loop exits after first empty retrieval. |
| Callback returns `{}` | Loop stops early (no more documents available). |
| Callback throws | Exception is caught; treated as empty result; loop continues or exits. |
| Duplicate PKs | Documents with the same `id` as an existing document are skipped during merge. |
| `max_retrieval_rounds` reached | Loop exits; final coverage/similarity determines `DetectionResult`. |
| `setVectorIndex(nullptr, ...)` | Vector search path in `handleRAG()` is bypassed; empty context is used. |
