SAFEITRATOR LIBRARY DESIGN (READY FOR PHASE 2)
================================================================================

FOUR CORE ABSTRACTIONS:

1. SafeIterator<T>
   ├─ Template wrapper for std::iterator
   ├─ Tracks container state (size, modification count)
   ├─ Validates bounds before dereference
   ├─ Detects container invalidation between operations
   ├─ Throws std::out_of_range or std::runtime_error on violation
   └─ Integration: Type B (Bounds) remediation

2. IteratorGuard<T>
   ├─ RAII-based container lock
   ├─ Prevents erase, clear, push_back during iteration
   ├─ Thread-safe std::mutex implementation
   ├─ Automatic unlock on scope exit
   └─ Integration: Type A (Invalidation) remediation

3. safe_advance()
   ├─ Bounds-checked std::advance wrapper
   ├─ Validates distance against container size
   ├─ Template specialization for iterator categories
   ├─ Prevents overflow for random-access iterators
   ├─ Throws std::out_of_range on bounds violation
   └─ Integration: Type C (Advance) remediation

4. BoundsCheckedRange<T>
   ├─ Range-based for loop wrapper
   ├─ Drop-in replacement for std::ranges
   ├─ Validates iterator != end() on each step
   ├─ Compatible with existing for-loops
   ├─ Minimal performance overhead (< 1%)
   └─ Integration: General safety wrapper

LIBRARY STRUCTURE:
  include/security/
    ├─ safe_iterator.h          (core class)
    ├─ iterator_guard.h         (RAII lock)
    ├─ safe_advance.h           (advance validation)
    ├─ bounds_checked_range.h   (range wrapper)
    └─ iterator_validation.h    (utilities)
    
  src/security/
    ├─ safe_iterator.cpp        (implementation)
    ├─ iterator_guard.cpp       (guard logic)
    ├─ safe_advance.cpp         (advance validation)
    └─ iterator_validation.cpp  (utilities)
    
  tests/
    ├─ test_safe_iterator.cpp   (40+ test cases)
    ├─ test_iterator_guard.cpp  (mutex tests)
    ├─ test_safe_advance.cpp    (boundary tests)
    └─ test_attack_vectors.cpp  (exploit tests)

PERFORMANCE TARGETS:
  └─ Non-error path overhead: < 5% vs baseline
  └─ Error path (exception): Complete safety check
  └─ Benchmark: Measured with google/benchmark

FIX PATTERNS BY TYPE:
  Type A → IteratorGuard pattern (prevent modification during iteration)
  Type B → SafeIterator pattern (bounds-check before access)
  Type C → safe_advance pattern (validate distance before advance)
