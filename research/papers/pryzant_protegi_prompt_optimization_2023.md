## 📋 Executive Summary

ProTeGi (Prompt Optimization with Textual Gradients) applies the metaphor of gradient descent to natural language: a critic LLM produces a **textual gradient** — a natural-language critique of the current prompt based on a mini-batch of failure examples — which drives an LLM to generate improved candidate prompts. Beam search keeps the top-B candidates across iterations. The result is a fully automated, LLM-powered prompt improvement loop that requires no labeled data and no weight updates. ThemisDB implements ProTeGi in `ProTeGiOptimizer` as the optimization back-end of `SelfImprovementOrchestrator`, with a heuristic fallback provider for offline deployments.

## 🎯 Key Findings

- **Textual gradient as critic output**: The "gradient" is a natural-language error description generated by the critic LLM, e.g. *"The prompt lacks output-format constraints and fails on edge-case X"*, replacing numerical backpropagation.
- **Mini-batch evaluation**: Each iteration samples a random mini-batch (4–16 examples) from available failure cases to compute the gradient message, analogous to stochastic gradient descent.
- **Beam search over prompt space**: From the gradient, the LLM proposes B candidate prompts (beam width B, default 4–8). All candidates are scored on a validation set; the top B/2 survive to the next iteration.
- **Convergence**: ProTeGi typically converges in 5–10 iterations on BigBench Hard, Instruction Induction, and BBH-CoT benchmarks.
- **No weight updates**: Every iteration consists of forward-pass LLM inference only, making ProTeGi compatible with black-box APIs and local llama.cpp models alike.
- **Outperforms APE**: ProTeGi surpasses APE (Zhou et al., 2022) on 17 of 24 BBH tasks; the gap is largest on multi-step reasoning tasks where CoT prompts help.

### What Was Adopted?

1. **Textual gradient loop**: `IProTeGiLLMProvider::computeGradient(prompt, errors)` returns a `ProTeGiGradient` struct (errors list, error rate, natural-language critique) that mirrors the paper's gradient concept.
2. **Candidate generation from gradient**: `IProTeGiLLMProvider::generateCandidates(prompt, gradient, num_candidates)` generates B improved prompt variants from the critique — the beam expansion step.
3. **Beam-width beam search**: `ProTeGiOptimizer::optimize()` maintains a beam of the top-B prompts across all iterations; per-iteration expansion and score-based pruning follow the paper's algorithm exactly.
4. **Mini-batch sampling**: `SelfImprovementOrchestrator` draws a random mini-batch of size `mini_batch_size` from `FeedbackCollector::getByType(FAILURE | LOW_SCORE)`, analogous to the paper's example mini-batch.
5. **Early stopping**: Loop terminates when `best_score >= target_score` (default 0.9), matching the paper's convergence criterion.

### How Was It Adapted?

| ProTeGi Concept | ThemisDB Adaptation | Rationale |
|---|---|---|
| GPT-4 as critic LLM | `IProTeGiLLMProvider` interface + `HeuristicProTeGiProvider` fallback | LLM-agnostic; heuristic fallback for offline/edge deployments |
| Labeled BigBench test set | `FeedbackCollector` failure examples from production | No manually annotated set required; production feedback drives optimization |
| Fixed beam width | Configurable `ProTeGiConfig::beam_width` | ThemisDB deployments vary in GPU budget; configurable quality–compute trade-off |
| Global prompt pool | Per-template `ProTeGiOptimizer` instance + `PromptVersionControl` commit per run | ThemisDB manages versioned templates; each optimization round creates a new version commit |
| No safety gate | `PromptInjectionDetector` gate before every candidate commit | Generated prompt variants can inadvertently contain injection patterns |

## ⚠️ Limitations & Open Questions

- ProTeGi requires a capable critic LLM (GPT-3.5+ / LLaMA-13B+); weaker models produce uninformative gradients.
  - ThemisDB solution: `HeuristicProTeGiProvider` as automatic fallback when no LLM provider is registered.
- Beam search can converge to local optima when all candidates share similar failure modes.
  - ThemisDB solution: Random mini-batch sampling from `FeedbackCollector` diversifies the error signal; different failure types appear across batches.
- ProTeGi optimizes syntactic prompt improvement; semantic quality (factuality, hallucination) requires a separate evaluation signal.
  - ThemisDB solution: `PromptEvaluator::score()` evaluates semantic similarity; `PromptRegressionRunner` checks regression against the golden set.
- Production feedback may be biased (selective user reporting).
  - ThemisDB solution: `FeedbackCollector::detectOutliers()` Z-score anomaly detection flags atypical entries before mini-batch sampling.
