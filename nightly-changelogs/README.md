# Nightly Build Changelogs

This directory contains automatically generated changelogs for each nightly build of ThemisDB.

## Overview

Every night at 2:00 AM UTC, when changes are detected in the repository, the nightly build workflow automatically:

1. Analyzes all commits from the last 24 hours
2. Identifies changed files and their types
3. Categorizes changes (features, bug fixes, documentation, refactoring)
4. Generates a detailed changelog document
5. Commits the changelog to this directory

## Changelog Format

Each changelog file is named `NIGHTLY_CHANGELOG_YYYY-MM-DD.md` and contains:

- **Build metadata**: Date, time, version
- **Commits**: List of all commits with authors
- **Changed files**: List of modified files with change types
- **File statistics**: Count of changed files by type (C++, Python, Markdown, YAML)
- **Change categories**: Count of features, bug fixes, documentation, and refactoring commits
- **Docker tags**: Available Docker image tags for this build

## Usage

### View Latest Nightly Changes

```bash
# View the most recent nightly changelog
ls -t nightly-changelogs/ | head -1 | xargs -I {} cat nightly-changelogs/{}
```

### Find Changes for Specific Date

```bash
# View changelog for a specific date
cat nightly-changelogs/NIGHTLY_CHANGELOG_2025-12-21.md
```

### List All Nightly Builds

```bash
# List all nightly changelog files
ls -1 nightly-changelogs/
```

## Automated Generation

The changelogs are automatically generated by the GitHub Actions workflow `.github/workflows/nightly-build.yml` in the `generate-changelog` job.

The generation process:
1. Uses `git log` to collect commits from the last 24 hours
2. Uses `git diff` to identify changed files
3. Analyzes commit messages for categorization
4. Formats everything into a structured Markdown document
5. Commits the changelog back to the repository

## Retention

- Changelog files are kept in the repository indefinitely
- They are also uploaded as workflow artifacts with 30-day retention
- Each file is approximately 1-5 KB in size

## Integration with Main Changelog

These nightly changelogs are separate from the main `CHANGELOG.md` file at the repository root, which follows [Keep a Changelog](https://keepachangelog.com/) format and documents official releases.

The nightly changelogs provide more granular, day-to-day visibility into development progress between releases.

## Example Changelog Structure

```markdown
# Nightly Build Changelog - 2025-12-21

**Build Time**: 2025-12-21 02:00:15 UTC
**Version**: 1.3.0

## Changes Since Last Build

### Commits

- Add feature X (abc123) - John Doe
- Fix bug Y (def456) - Jane Smith
- Update documentation (ghi789) - Bob Johnson

### Changed Files

\`\`\`
M    src/core/database.cpp
A    src/features/new_feature.cpp
M    docs/api.md
D    old_file.cpp
\`\`\`

### File Statistics

- C++ files: 15
- Python files: 3
- Markdown files: 5
- YAML files: 1

### Change Categories

- Features: 5 commits
- Bug Fixes: 2 commits
- Documentation: 3 commits
- Refactoring: 1 commits

---

**Docker Tags Available**:
- \`themisdb/server:nightly\`
- \`themisdb/server:nightly-20251221\`
- \`themisdb/server:1.3.0-nightly\`
```

## Troubleshooting

If a nightly build is skipped due to no changes, no changelog will be generated for that day. This is expected behavior and helps keep the repository clean.

To force a changelog generation, manually trigger the nightly build workflow with the "Force build" option enabled.
