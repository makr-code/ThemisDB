### Title
[PERF-D7] Query Engine: 47% Speedup vs ClickHouse via SIMD Column Compression

### Labels
performance, query-engine, simd, medium-priority

### Description:
## Problem
Query engine throughput is 814.5 M items/s, but target is 1.200 M items/s. This represents a 47% gap (-47%) vs ClickHouse baseline.

### Root Cause Analysis
The current query executor materializes columns too early and lacks aggressive SIMD optimizations for columnar operations.

**Current Execution Path:**
```cpp
// src/query/executor.cpp
for (each row in table) {
    // Materialize column values (unpacked)
    auto col_a = getColumn(row, col_id_a);  // Scalar
    auto col_b = getColumn(row, col_id_b);  // Scalar
    
    // Apply predicate
    if (col_a > threshold && col_b < limit) {
        result.push_back(row);
    }
}
// No vectorization → CPU struggles with dependency chains
```

### Performance Bottlenecks
1. **Row-wise Evaluation:** No SIMD parallelism (1 row at a time)
2. **Early Materialization:** Unpacks columns before filtering (wasted I/O)
3. **Scalar Predicates:** No vectorized comparison operations
4. **No Compression:** Fetches raw values (8-16 bytes per value)
5. **Poor Cache Utilization:** Random access patterns
6. **Dependency Chains:** CPU stalls waiting for comparisons

### Performance Target Breakdown
- **Target:** 1.200 M items/s = 833 ps/item
- **Current:** 814.5 M items/s = 1.23 ns/item
- **Gap:** 0.4 ns/item improvement needed (47% throughput boost)

## Solution Strategies

### Strategy 1: Lazy Evaluation + Predicate Pushdown (Recommended - Medium Effort)
**Approach:** Evaluate predicates on compressed columns before materialization
- Parse filter expressions into predicate trees
- Evaluate column comparisons on compressed blocks
- Only materialize filtered rows
- Expected gain: +1.3-1.5× throughput (47-50%)
- **Effort:** 4-5 weeks

**Implementation:**
```cpp
// Proposed: LazyEvaluator (src/query/lazy_evaluator.cpp)

    std::vector<uint32_t> evaluatePredicate(
        const ColumnBlock& block,
        const Predicate& pred) {
        
        // 1. Evaluate on compressed data (no materialization)
```

### Strategy 2: Dictionary-Encoded Column Scanning (Higher Complexity)
**Approach:** Store columns as dictionaries, evaluate on dictionary values
- Cardinality analysis: Identify low-cardinality columns
- Dictionary encoding: Map values to small integer IDs (1-4 bytes)
- Filter on dictionary (super fast)
- Expected gain: +2-2.5× throughput (additional benefit)
- **Effort:** 5-6 weeks

### Strategy 3: Columnar SIMD Joins (Very High Effort, Highest Performance)
**Approach:** Vectorize inner join operations across columns
- Process 16+ columns in parallel for join conditions
- Use AVX-512 for 8× uint64_t comparisons
- Expected gain: +1.5-3× throughput (cumulative)
- **Effort:** 7-9 weeks
