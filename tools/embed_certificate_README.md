# ThemisDB Embedded Certificate Tool

## Overview

The `embed_certificate` tool converts ThemisDB X.509 certificates and digital signatures into C++ const array headers that can be embedded directly in plugin binaries. This enables Level 2 (Embedded Signature) verification without relying on external metadata files.

## Features

- ✅ Convert X.509 certificates (DER or PEM format) to C++ arrays
- ✅ Embed digital signatures as const arrays
- ✅ Generate portable C++ headers with no external dependencies
- ✅ Customizable namespace and array naming
- ✅ Automatic include guards
- ✅ Build-time integration via CMake

## Usage

### Command Line

```bash
# Basic usage - embed certificate only
embed_certificate --cert themisdb-ca.crt --output embedded_cert.h

# Embed certificate and signature
embed_certificate \
    --cert themisdb-plugin-signer.crt \
    --signature plugin.sig \
    --output plugin_cert.h

# Custom namespace and plugin name
embed_certificate \
    --cert signer.crt \
    --plugin-name onnx_clip \
    --namespace "themis::plugins" \
    --output onnx_clip_cert.h
```

### Options

| Option | Description | Default |
|--------|-------------|---------|
| `--cert <file>` | Path to certificate file (DER or PEM) | Required |
| `--signature <file>` | Path to signature file (binary) | Optional |
| `--output <file>` | Output header file path | `plugin_embedded_cert.h` |
| `--namespace <ns>` | C++ namespace for arrays | `themis::plugins` |
| `--plugin-name <name>` | Plugin name for array identifiers | None |
| `--help` | Show help message | - |

## CMake Integration

### Automatic Embedding During Build

```cmake
# In plugin CMakeLists.txt
include(SignPlugin)

add_library(my_plugin SHARED
    my_plugin.cpp
)

# Option 1: Full signing with embedded certificate (production)
set(THEMIS_SIGN_PLUGINS ON)
sign_plugin(my_plugin)

# Option 2: Embedded certificate only (development)
set(THEMIS_EMBED_CERTIFICATES ON)
embed_certificate_in_plugin(my_plugin)
```

### Custom Certificate Path

```cmake
# Use a different certificate
embed_certificate_in_plugin(my_plugin "/path/to/custom.crt")
```

## Using Embedded Certificates in Plugin Code

### Reading Embedded Certificate

```cpp
#include "my_plugin_embedded_cert.h"
#include <openssl/x509.h>

// Parse embedded certificate
X509* loadEmbeddedCertificate() {
    const unsigned char* p = themis::plugins::THEMISDB_MY_PLUGIN_CERT;
    X509* cert = d2i_X509(
        nullptr, 
        &p, 
        themis::plugins::THEMISDB_MY_PLUGIN_CERT_LEN
    );
    return cert;
}
```

### Verification Example

```cpp
#include "my_plugin_embedded_cert.h"
#include "acceleration/plugin_security.h"

bool verifyPluginWithEmbedded() {
    using namespace themis::acceleration;
    using namespace themis::plugins;
    
    // The EnhancedPluginSecurityVerifier will automatically
    // extract and verify the embedded certificate
    PluginSecurityPolicy policy;
    policy.requireSignature = true;
    
    EnhancedPluginSecurityVerifier verifier(policy);
    auto result = verifier.verifyPlugin(
        "./my_plugin.so",
        EnhancedPluginSecurityVerifier::VerificationLevel::LEVEL_2_EMBEDDED_SIGNATURE
    );
    
    return result.passed && result.is_themisdb_official;
}
```

## Certificate Formats

### Supported Input Formats

1. **DER (Distinguished Encoding Rules)**
   - Binary format
   - Most compact
   - Recommended for embedding
   - File extension: `.crt`, `.cer`, `.der`

2. **PEM (Privacy-Enhanced Mail)**
   - Base64-encoded DER
   - ASCII text format
   - Contains `-----BEGIN CERTIFICATE-----` header
   - File extension: `.pem`, `.crt`

### Converting Between Formats

```bash
# PEM to DER
openssl x509 -in cert.pem -outform DER -out cert.der

# DER to PEM
openssl x509 -in cert.der -inform DER -outform PEM -out cert.pem

# View certificate details
openssl x509 -in cert.pem -text -noout
```

## Build Requirements

- **Compiler**: C++17 or later
- **Dependencies**: Standard library only (no external deps)
- **Build time**: < 1 second
- **Output size**: Typically 1-5 KB per header

## Examples

### Example 1: Basic Certificate Embedding

```bash
# Generate CA certificate header
embed_certificate \
    --cert certs/manufacturer/themisdb-ca.crt \
    --output include/themis_ca_embedded.h \
    --namespace "themis::security"
```

### Example 2: Plugin with Signature

```bash
# 1. Generate plugin signature
openssl dgst -sha256 -sign private.key -out plugin.sig plugin.so

# 2. Embed certificate and signature
embed_certificate \
    --cert themisdb-plugin-signer.crt \
    --signature plugin.sig \
    --plugin-name onnx_clip \
    --output onnx_clip_cert.h
```

### Example 3: Multiple Plugins

```bash
# Embed certificates for all plugins
for plugin in clip yolo whisper; do
    embed_certificate \
        --cert themisdb-plugin-signer.crt \
        --plugin-name $plugin \
        --output ${plugin}_cert.h
done
```

## Troubleshooting

### Tool Not Found

```
Error: embed_certificate tool not found
```

**Solution**: Build the tool first:
```bash
cmake -B build
cmake --build build --target embed_certificate
```

### Certificate Parse Error

```
Error: Failed to read file: cert.crt
```

**Solutions**:
- Verify file path is correct
- Check file permissions
- Ensure certificate is in DER or PEM format
- Try converting to DER: `openssl x509 -in cert.pem -outform DER -out cert.der`

### Output Header Issues

```
Error: Failed to create output file
```

**Solutions**:
- Check output directory exists
- Verify write permissions
- Ensure output path is valid

## Security Notes

⚠️ **Important Security Considerations:**

1. **Private Keys**: Never embed private keys in headers! Only certificates (public keys) should be embedded.

2. **Certificate Validation**: Embedded certificates must still be validated:
   - Check expiration dates
   - Verify certificate chain
   - Check revocation status (CRL/OCSP)

3. **Signature Freshness**: Embedded signatures should be regenerated for each build to prevent replay attacks.

4. **Source Control**: It's safe to commit generated headers to Git as they contain only public certificates.

## Integration with EnhancedPluginSecurityVerifier

The embedded certificates work seamlessly with the multi-level verification system:

| Level | Description | Uses Embedded Cert? |
|-------|-------------|---------------------|
| Level 1 | Hash-only | ❌ No |
| Level 2 | Embedded signature | ✅ **Yes** |
| Level 3 | Platform signature | Optional |
| Level 4 | Full chain + CRL/OCSP | ✅ Yes |

## Performance

- **Header generation**: < 100ms for typical certificates
- **Binary size overhead**: ~1-2 KB per embedded certificate
- **Runtime parsing**: ~1-5ms using OpenSSL d2i_X509()
- **Build time impact**: Negligible (only runs when cert changes)
